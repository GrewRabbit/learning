# Spec 正文模板

> 适用角色：`nextjs-spec-generator` | 优先级：高

每份 spec 正文**必须**包含以下结构。此模板用于 `nextjs-spec-generator` 生成初稿。

---

## 模板结构

```markdown
# [功能名称] 需求规格文档

**版本**：v1.0
**状态**：draft | in-review | approved
**创建时间**：YYYY-MM-DD
**最后更新**：YYYY-MM-DD

## 变更记录

| 版本 | 日期 | 变更内容 | 参考评审 |
|------|------|---------|---------|
| v1.0 | ... | 初稿创建 | — |
| v1.1 | ... | 根据 r1 评审修订认证流程描述 | review-r1 |

## 1. 背景与目标

（说明为什么需要这个功能，要解决什么问题，预期达到什么效果）

## 2. 用户故事

（以用户视角描述功能场景，格式：作为[角色]，我想要[功能]，以便[价值]）

## 3. 功能需求

（按模块列出具体功能点，每个需求编号便于评审引用）

### 3.1 [模块名]

- **FR-001**：[需求描述]
- **FR-002**：[需求描述]

## 4. 非功能需求

（性能、安全、可访问性、兼容性等约束）

## 5. 边界与排除项

（明确不做什么，划定范围边界）

## 6. 验收标准

（可测试、可验证的通过条件，用 checkbox 列表）

- [ ] AC-001：[验收条件描述]
- [ ] AC-002：[验收条件描述]
```

---

## 评审意见文件模板

```markdown
# [功能名称] 评审意见 — 第 N 轮

**评审对象**：spec-[feature-slug]-v[x.x].md
**评审时间**：YYYY-MM-DD
**评审结论**：需修订 | 通过

## 问题清单

| 编号 | 位置 | 问题描述 | 严重程度 | 修订建议 |
|------|------|---------|---------|---------|
| R1-001 | §3.2 | ... | 阻塞/重要/建议 | ... |

## 评审总结

（简要说明本轮核心问题与修订方向）
```
