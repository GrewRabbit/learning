# 更新日志规范

> 适用角色：所有 Agent | 优先级：最高

---

## 一、何时需要写更新日志

**核心原则**：仅"结构化修改"需要记录，"小修改"无需记录。

### 必须写更新日志的变更（结构化修改）

| 类型 | 示例 |
|------|------|
| 新增模块 / 文件 / 接口 | 新增 `FsHtmlCache` 实现、新增 API 端点 |
| 修改架构 | 数据流变更、组件边界调整、新增/移除抽象层 |
| 引入新依赖 | package.json 新增 dependencies |
| 跨文件协同修改 | 一个功能涉及 ≥ 3 个文件联动改动 |
| 数据 / 缓存策略变更 | 缓存驱动切换、表结构变更、key 规则变化 |
| 影响配置 | 新增环境变量、修改 config 文件、调整运行时参数 |
| 影响业务流程 | 用户操作路径变化、API 契约变化（请求/响应字段增删） |
| 影响部署 | Dockerfile 变化、CI/CD 流水线调整、运行时要求变化 |
| 安全相关 | 鉴权策略、CSP / CORS 调整、Cookie 配置变化 |
| 移除 / 废弃功能 | 删除 API、废弃组件、下线模块 |

### 不需要写更新日志的变更（小修改）

| 类型 | 示例 |
|------|------|
| UI 微调 | 颜色、字体、间距、圆角、阴影调整 |
| 输入验证微调 | 调整字段长度限制、增加正则规则 |
| 文案修改 | 提示文字、按钮文字、注释调整 |
| 单点 Bug 修复 | 不涉及架构调整的单文件修复 |
| 重命名 | 变量 / 函数 / 文件重命名（无功能变化） |
| 格式化 | 代码缩进、import 顺序、Prettier 格式化 |
| 测试用例增补 | 仅新增 / 修改测试代码，不动业务代码 |

### 边界判定

- **拿不准时**：写。多记录优于漏记录。
- **混合变更**：一次提交同时含小修改 + 结构化修改 → 写，但只描述结构化部分。
- **批量小修改**：连续多次同类小修改（如一周内 5 次颜色调整）→ 可在周末汇总写一条。

## 二、更新日志存放位置

```
docs/
  changelog/                              ← 所有更新日志
    2026-06-30-HTML本地文件缓存.md
    2026-07-01-多解法数据库存储.md
    ...
```

## 三、文件命名规范

```
YYYY-MM-DD-简短中文描述.md
```

**规则**：

- 日期为变更**实施日期**（非计划日期）
- 简短描述用中文，6-15 字，体现变更核心
- 同一天多个变更：合并为一份，按时间顺序列多个章节
- 文件名避免特殊符号（除连字符 `-`）

**示例**：

```
✅ 2026-06-30-HTML本地文件缓存.md
✅ 2026-07-05-多解法数据库存储改造.md
❌ 2026-6-30-html cache.md         （月份未补零、英文+空格）
❌ 20260630-缓存.md                  （日期格式不对、描述过简）
```

## 四、更新日志正文模板

每份更新日志**必须**包含以下结构：

```markdown
# [变更标题]

**日期**：YYYY-MM-DD
**类型**：新增 | 优化 | 重构 | 修复 | 文档
**影响范围**：[受影响的模块 / 页面 / API 路径]

## 变更背景

（说明为什么做这个变更，要解决什么问题）

## 变更内容

### [子模块 1]

- 具体改动点 1
- 具体改动点 2

### [子模块 2]

- 具体改动点

## 涉及文件

| 文件路径 | 变更类型 | 说明 |
|---------|---------|------|
| `app/lib/ai/services/fs-html-cache.ts` | 新增 | 文件系统缓存实现 |
| `app/lib/ai/services/html-cache.ts` | 修改 | 添加驱动切换逻辑 |

## 配置 / 环境变量变化

| 变量名 | 默认值 | 说明 |
|--------|--------|------|
| `GESP6_CACHE_DRIVER` | `memory` | 缓存驱动：`memory` / `fs` |
| `GESP6_CACHE_FS_DIR` | `/var/learning/data/gesp6` | fs 驱动下的缓存根目录 |

（无变化时写"无"）

## 验证方式

- [ ] 类型检查：`npm run type-check`
- [ ] 单元测试：`npm test`
- [ ] Lint：`npm run lint`
- [ ] 手动验证：[具体步骤]

## 后续影响 / 注意事项

（对后续开发、部署、运维的影响，如需要重启服务、需要数据库迁移等）
```

## 五、强制执行规则

1. **PR / Commit 前**：实施结构化修改后，**必须**在 `docs/changelog/` 下创建对应更新日志
2. **Git 提交信息**：提交描述中**必须**引用对应的更新日志文件路径
3. **评审检查**：代码评审时**必须**检查是否漏写更新日志
4. **更新日志只追加不修改**：归档后的更新日志文件**禁止修改**（写错了在新文件中追加勘误）

## 六、与其他规则的关系

- 本规范与 [git-commit.md](./git-commit.md) 互补：git-commit 规范描述**提交信息格式**，本规范描述**何时需要独立文档化**
- 本规范与 [naming-conventions.md](./naming-conventions.md) 协同：更新日志文件名遵循命名规范
