# SSO Token 生命周期与安全强化 评审意见 — 第 1 轮

**评审对象**：spec-sso-token-v1.0.md
**评审时间**：2026-08-10
**评审结论**：需修订

## 评审总结

**核心结论**：本 spec 对集成指南契约的引用整体准确（已逐条核对 §3.3/§3.6/§3.7/§4.2/§4.3/§5.4-§5.8/§6.5/§7.1 相关条目，未发现契约曲解）；§3.6 Introspect 自定义扩展已正确声明且契约引用准确（§0.2 能力映射表确认 Introspect 未列入任何任务路径，与 spec 声明一致）；未照搬集成指南示例代码；错误码格式合规；未混入架构设计内容。但存在 4 个重要级问题需修订后进入第 2 轮。

**各维度结论**：

1. **完整性**：模板六章齐全，FR/AC/NFR/B/OQ 编号连续（FR-001~026、AC-001~026、NFR-001~007、B-001~007、OQ-01~10）。
2. **可追溯性**：每个 FR 均标注契约来源或安全基线；业务目标缺失已声明（B-007）并挂 OQ，未自行决断，合规。
3. **准确性**：契约引用总体准确；个别引用位置偏差（V-025/026/027 实属 §7.1.4，R1-007）与语义混用（429 处理，R1-005）。
4. **第三方对齐**：expires_in 900s、refresh_token 轮换、Revoke 200 语义、R1-010 hint 缺陷均与集成指南一致；主要缺口为刷新后新 access_token 的更新遗漏（R1-002，重要）与跨标签页重放撤销全会话风险（R1-004，重要）。
5. **可测试性**：AC 总体可测（可控时钟、mock、bundle 扫描、日志扫描手段齐备）；「可配置」类 AC 缺配置键与验证方式（R1-006）。
6. **边界清晰度**：DPoP/PAR/DCR/Back-Channel Logout/client_credentials 排除明确；但与登录流程的边界存在矛盾（R1-003，重要）。
7. **合规性**：无照搬示例代码、无架构设计混入、错误码格式合规；正文混入流程性元注释（R1-012）。
8. **一致性**：FR↔AC 一一对应无冗余；FR-017 与 AC-017 强弱不一致（R1-001，重要）。
9. **安全性**：fail-closed、client_secret 保护、日志脱敏、revoke 后端转发、轮换防重放覆盖完整；缺重放检测的安全告警记录要求（R1-008）。
10. **现状对齐**：middleware 匿名模式、限流参数、Edge Runtime 约束、GESP6_* 错误码风格引用准确；FR-024 未充分指出 middleware matcher 仅覆盖 /api/* 的现状（R1-014）。

**修订方向**：优先修订 4 个重要级问题（R1-001~R1-004）——统一内省触发语义、补齐刷新后 access_token 更新、澄清与登录流程的范围边界、补强跨标签页并发风险；建议级问题可在同一轮修订中一并处理。
