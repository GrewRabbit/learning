## 一、七项评审重点结论

### 1. 全站登录墙范围与公开白名单

- 主体表述无歧义：FR-028 将白名单显式化为 `/`、`/login`、`/api/sso/*`、`/api/health`，与 D-001/D-004 决策一致；「白名单之外的**全部页面路由与 API 均需登录态**」兜底表述清晰。
- `/_next/*` 静态资源与 favicon 不被拦截约束已体现（FR-028：「不得被认证拦截」，matcher 豁免细节归架构文档 D-002）。✓
- 首页 `/` 公开语义已被正确规格化，且四处一致：FR-028（「不强推登录、不展示个人信息」）、US-006、AC-037、OQ-002。✓
- 遗留问题：R1-001（「等运维接口」含糊）、R1-002（`[locale]` 前缀首页未入白名单）。

### 2. 页面层校验衔接

- FR-029 与既有两层运行结构一致：middleware 层 cookie 级粗检（明确「Edge 约束一致、禁引用 SSO 密钥环境变量」，未破坏 FR-024 约束）+ Node 层深度校验（沿用 guard.ts requireAuth fail-closed 语义），落点归架构阶段。✓
- 未登录 302 → `/login` 带 returnTo 行为与 FR-005（持久化双写）与 FR-023（开放重定向校验）衔接一致。✓
- 遗留问题：R1-003（API 302 语义与 returnTo 适用性）、R1-004（Node 层触发条件含糊）、R1-010（Node 层失败行为未定义）。

### 3. /login 登录入口页

- FR-030 三职责完整覆盖：① 登录态检测 + 已登录重定向（默认落地页正确挂起 OQ-009）；② SP-Initiated authorize 跳转 + returnTo 透传（FR-005 + FR-023 校验）；③ 登录流程错误提示脱敏（FR-026）。源码核对：代码库确实不存在 `/login` 路由（glob 确认仅 app/page.tsx、solve、result 三个 page），「新增需求」陈述准确。✓
- 遗留问题：R1-005（①重定向未显式引用 FR-023、无自引用循环防护）、R1-006（「自动触发」语义不明）。

### 4. 超范围检查（对比 v1.2 基线）

- 已确认机制全部保留、未被意外改动或删除：错误码分区制（§3.7）、过期即重登（FR-017）、续期衔接（FR-018）、cookie 属性单一来源（FR-015）、nonce 持久化（FR-003）、登出编排（FR-019~FR-023）、状态 cookie 服务端写入（FR-003）。FR-001~FR-027 与 AC-001~AC-034 全部保留，仅 FR-016/AC-018 因范围扩展做了必要修改。✓
- 变更基本收敛于 D-001~D-006；遗留：R1-007（§1.1 背景事实修正未入变更记录）。

### 5. 交叉引用一致性

- auth v1.3 引用 token v1.2（approved）版本正确；§3.7 错误码分区制保持，R2-001 结论与 token v1.2 FR-025 实际修订状态核对一致。✓
- token v1.2 引用的 auth 版本号过时（B-001/§1.2/FR-025 写「spec-sso-auth v1.1，draft」），auth v1.3 未标注：R1-008。
- FR/AC 编号连续：FR-001~FR-030、AC-001~AC-038 均连续无跳号。✓
- token OQ-02 适用范围已被全站登录墙覆盖的同步提示已写入 OQ-010 v1.3 补充段。✓

### 6. FR/AC 可测性

- FR-028/029/030 与 AC-035~038 均可测试：AC-035（白名单 + `/_next/*` 豁免，E2E @smoke + 静态检查）、AC-036（页面 302 + returnTo + 回跳，E2E @smoke）、AC-037（首页公开，E2E @smoke）、AC-038（/login 三职责，E2E @smoke + 单测）。AC-038 对 OQ-009 未决项的断言门控正确（「OQ-009 未决前不作该目标断言」）。✓
- 遗留：R1-009（NFR-003 @smoke 描述未含页面场景，与 AC-035~038 不完全对齐）。

### 7. OQ 裁决状态

- OQ-002（全站登录墙）、OQ-003（/login 保留并落地）转已裁决恰当，标注业务方确认时间 2026-08-11；OQ-001 部分裁决（范围已定、会话/登出体验仍待确认）恰当；OQ-010 已裁决且 v1.3 补充段新增 token OQ-02 同步提示恰当。✓
- OQ-009（默认落地页）正确保持开放，且 FR-030/AC-038 均正确引用该未决状态。✓
- 遗留：R1-011（OQ-009 候选表述与新登录墙语义的对齐）。

## 三、重要问题的修改意见段落（可直接替换，不改动 spec 正文）

### R1-001 — FR-028 白名单「等运维接口」替换建议

> 原句：「`/api/health` 等运维接口」
>
> 替换为：「`/api/health`（运维接口白名单的**具体枚举由架构阶段 matcher 表达式落实**，本 spec 约束：运维接口仅限健康检查/探活类端点，不得包含业务数据端点）」。

### R1-002 — FR-028 补充 `[locale]` 前缀首页公开语义

> 在 FR-028 白名单条目后追加：
>
> 「`[locale]` 国际化前缀落地后，locale 前缀下的首页路径（如 `/<locale>`）延续 `/` 的公开语义（不强推登录、不展示个人信息），对应 locale 前缀下的受保护页面（如 `/<locale>/solve`、`/<locale>/result`）仍须登录（FR-029）。」
>
> 同时 FR-029 中「含未来 `[locale]` 国际化前缀下的对应路径」保持不动，两处形成对称。

## 四、评审总结

- 本次为业务决策变更修订（D-001~D-006），核心变更（全站登录墙范围、白名单显式化、页面路由登录、/login 入口页落地、认证基础设施先行原则）均已完整落入 v1.3，且与 D-001~D-006、OQ-001~OQ-003 裁决、源码现状核对一致。
- **无阻塞问题**：未发现违反需求基线或安全/逻辑矛盾；已确认机制（错误码分区制、过期即重登、续期衔接、cookie 属性单一来源、nonce 持久化、登出编排、状态 cookie 服务端写入）全部保留。
- **2 项重要级**（R1-001 白名单边界不可穷举、R1-002 locale 首页公开语义缺口）：均不影响当前实施（matcher 细节归架构、locale 未落地），但应在终审前修订，避免架构阶段与 locale 落地后产生歧义。
- **9 项建议级**：多为表述精确化与文档一致性（R1-003~R1-011），可随重要级一并修订，其中 R1-008（token v1.2 引用 auth 版本过时）建议至少以标注形式处理，供 token spec 下一轮修订参照。
- 修订方向：按 §三 修改意见段落修订 FR-028/FR-029 与变更记录后，本 spec 可进入终审；FR/AC 编号、章节结构、行数（246 行 < 500）均合规。
