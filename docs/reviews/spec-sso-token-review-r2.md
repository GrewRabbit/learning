| R2-001 | §3.6 FR-025 / 交叉核对 spec-sso-auth §3.7 | 错误码 `AUTH_LOGIN_INVALID_CREDENTIALS` 归属循环引用：token spec FR-025 将其列入登录流程错误码并声明「登录流程错误码清单以 spec-sso-auth §3.7 为事实来源」，但 auth spec §3.7 错误码表并未定义该码（其归属边界段落又将 `AUTH_LOGIN_INVALID_CREDENTIALS` 列入「以 token spec FR-025 为唯一事实来源」的清单）。双方互相指向对方，无任何一处定义其触发场景。且 SSO 走 authorization code + PKCE 流程、无本地凭据校验步骤，该码疑为 LDAP 风格残留（middleware 注释中「SSO/LDAP」并列项的遗留），可能永远无触发路径 | 重要 | 与 auth spec 协调后二选一：(a) 若确有触发场景（如 LDAP 路径），由 auth spec §3.7 补充定义触发场景；(b) 若无场景，从 token spec FR-025 清单移除，并在 FR-025 注明「登录流程错误码以 spec-sso-auth §3.7 为唯一事实来源，本清单不预留学生用错误码」，避免幽灵预留 |

## 评审总结

**核心结论**：本 spec 对集成指南契约的引用经逐条核对（§0.2、§1.6、§3.3、§3.6、§3.7、§3.8、§4.2、§4.3.1、§5.4~§5.8、§6.3~§6.5、§7.1.2/7.1.3）仍全部准确；§3.6 Introspect 自定义扩展声明准确（§0.2 能力映射表确认 Introspect 未列入任何任务路径，与 spec 声明一致）且契约引用精确（含 R1-010 hint 缺陷的正确解读）；未照搬集成指南示例代码；错误码格式合规；未混入架构设计决策（技术选型均挂 OQ 或留待架构阶段）。上轮 R1-001~R1-015 全部解决（15/15，解决率 100%）。但本轮发现 3 个新的重要级问题，均集中于**跨 spec 一致性**：错误码归属循环引用（R2-001）、登出域重复规格化且细节不一致（R2-002）、FR-003 与 auth FR-016 运行时分层的衔接缺失及校验对象表述不一致（R2-003）。结论：需修订。

**各维度结论**：

1. **完整性**：模板六章齐全；FR/AC 编号连续（FR-001~026、AC-001~026、NFR-001~007、B-001~007、OQ-01~10）；变更记录完整。
2. **可追溯性**：每个 FR 均标注契约来源或安全基线；业务目标缺失已声明（B-007）并挂 OQ，未自行决断，合规。个别引用精确性不足（R2-009）。
3. **准确性**：契约引用总体准确；§3.6 扩展声明与 R1-010 解读准确；无曲解 IDP 能力或端点行为。
4. **第三方对齐**：expires_in 900s、refresh_token 轮换（含刷新后 access_token 更新）、Revoke 200 语义（RFC 7009）、Introspect active 语义、会话超时 15 分钟粒度均与集成指南一致；跨标签页重放撤销全会话风险已充分暴露（FR-005/OQ-05）。
5. **可测试性**：AC 总体可测（可控时钟、mock、bundle 扫描、日志扫描）；「存在有效性确认步骤」断言偏弱（R2-007）、AC-003 依赖 OQ-04（R2-006）。
6. **边界清晰度**：B-001~B-007 明确不做什么；与登录流程的初始 token 写入衔接清晰（auth FR-015）；登出域白名单校验与 auth FR-022 重复且不一致（R2-002）。
7. **合规性**：无照搬示例代码、无架构设计混入（候选缓解方向为开放问题选项列举，合规）、错误码格式合规（AUTH_* 全大写 MODULE_CATEGORY_SPECIFIC）；跨 spec 引用版本过时（R2-010）。
8. **一致性**：FR↔AC 一一对应无冗余；FR-003 判定依据与 auth FR-016 分层衔接缺失（R2-003）；FR-023 与 FR-010 重试上限语义未统一（R2-008）。
9. **安全性**：refresh_token 轮换防重放、revoke 后端转发、内省 fail-closed、会话超时、日志脱敏、client_secret 保护、跨标签页并发风险覆盖完整；登出白名单回退规则遗漏风险（R2-002）为新增安全关注点。
10. **现状对齐**：middleware 匿名模式、matcher /api/:path* 范围、Edge Runtime 约束（OQ-06）、env.ts 无 SSO_* 变量、GESP6_* 错误码风格引用均准确；FR-003 未区分 Edge/Node 分层（R2-003）。

**修订方向**：优先解决 3 个重要级问题——与 auth spec 协调错误码归属（R2-001）、指定登出白名单校验单一描述来源（R2-002）、补 FR-003 运行时分层衔接并统一校验对象表述（R2-003）；建议级问题可同轮一并处理。修订后进入第 3 轮评审（本方案强制满 2 轮评审，本轮无论结论均不直接 approved）。
