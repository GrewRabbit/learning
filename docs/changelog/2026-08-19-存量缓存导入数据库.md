# 存量缓存一次性导入数据库（db:import 脚本 + 实测入库）

**日期**：2026-08-19
**类型**：新增
**影响范围**：`scripts/migrate-fs-cache-to-db.ts`（新增）、`package.json`（scripts）、数据库 `gesp6_billing` 的 `solutions` / `primary_indexes` / `sample_indexes` 三表（已导入 108/22/9 行）

## 变更背景

数据库与业务系统整合（spec-db-integration-v1.0 FR-023~026）要求把 `data/gesp6/` 文件系统缓存的存量数据（content 108 对 html+json、primary 22、sample 9）一次性导入 PostgreSQL，作为后续切换 `GESP6_CACHE_DRIVER=db`（T9 部署阶段）的数据基线，避免旧题重新调用 LLM 生成造成成本浪费。本次落地导入脚本并在真实库完成 AC-021/022/023 三项验收实测。

## 变更内容

### 导入脚本 `scripts/migrate-fs-cache-to-db.ts`

- 扫描阶段（FR-025a 成对校验）：`scanContentDir` 以文件名（去后缀）为 hash 键做 html/json 成对校验（缺一侧 / json 解析失败 / validated 非 boolean → 失败清单，该 hash 整体跳过）；`scanPrimaryDir` 按文件名**首个下划线**分割 platform/problemId（防御 problemId 含 `_`）；`scanSampleDir` 以文件名为 sampleFp；warning 缺失 → null，createdAt 缺失/非法 → 兜底 now() + WARN 不阻塞
- 导入阶段：固定顺序 solutions → primary_indexes → sample_indexes（索引表 FK 依赖），逐行调用 `solutionDao.insertIfAbsent*`（ON CONFLICT DO NOTHING，幂等）；单行失败（悬空索引 FK 违反 / IO 异常）仅该行入失败清单、其余继续（FR-025c）
- 报告与退出码（FR-025b/FR-033）：扫描统计 + 每表 scanned/imported/skipped/failed 四计数 + 失败明细（source + reason）；任一失败 → 退出码 1（`GESP6_MIGRATION_VALIDATION_FAILED` 语义），全成功（含 skipped）→ 0；结束后 `getPool().end()` 收尾连接池

### package.json

- 新增 scripts：`"db:import": "tsx scripts/migrate-fs-cache-to-db.ts"`

### 与设计文档（arch-db-integration-import.md）的两处等价实现偏差

1. §3「每批一事务」→ **逐行 insertIfAbsent\***（T2 定稿 DAO 签名不收 tx 参数）：pg 单条 INSERT ... ON CONFLICT DO NOTHING 语句本身原子，BATCH_SIZE=500 保留为进度分片语义，失败隔离粒度细化到行；108+22+9 行规模下单行语句开销可忽略，DO NOTHING 幂等不依赖跨行原子性
2. §2.1 createdAt「ISO 直接写入」→ DAO 签名不携带 createdAt，由 schema `defaultNow()` 兜底（与「缺失/非法 → now()」语义一致）；扫描期仍做 createdAt 校验与 WARN

## 后续影响 / 注意事项

- T9 部署阶段执行 `GESP6_CACHE_DRIVER=db` 切换前，需按统一部署步骤确认：先 `db:migrate` → `db:import` → 全部实例同步切换（R-03）；切换后 fs 缓存停用但代码与数据保留（FR-026 回退能力）
- 导入数据的 `created_at` 为导入时刻（DB `defaultNow()`），非 fs 元数据中的历史时间（见上文偏差 2）；如需保留历史时间需扩展 DAO 签名，当前无业务依赖该时间字段
- 多实例并发写场景：导入应在维护窗口执行或依赖幂等重跑补导（R-02）；脚本可修复后重跑，只补差量
