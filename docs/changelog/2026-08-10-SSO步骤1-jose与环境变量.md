# SSO 步骤 1：jose 依赖引入与 SSO 环境变量扩展

**日期**：2026-08-10
**类型**：新增
**影响范围**：`package.json`（dependencies）、`app/lib/env.ts`（validateEnv / getSsoEnv）、`app/lib/__tests__/env.test.ts`

## 变更背景

实施 SSO 集成架构 §11 步骤 1（模块 M8）：为 SSO 登录认证准备基础依赖与服务端环境变量。此前项目无 JWT 处理库、无 SSO 配置项；`app/lib/env.ts` 的 `validateEnv` 无任何 SSO 校验分支。

## 变更内容

### jose ^6.2.8 引入（package.json dependencies）

- `npm view jose versions` 验证 `^6.2.8` 存在后加入 dependencies（实现中选择 v6 语义；v6 的 `JWTClaimVerificationOptions` 无 `nonce` 选项，第 8 步 nonce 比对改为手动实现——见步骤 4 changelog）
- 供 JWT 验签（RS256）、JWKS 导入（`importJWK`）、cookie exp 解码使用

### `app/lib/env.ts` SSO 环境变量扩展

- 新增 `SsoEnvConfig` 类型与 `getSsoEnv()`（每次调用先走 `validateSsoEnvVars()` 校验）
- 新增校验：`NEXT_PUBLIC_SSO_CLIENT_SECRET` 存在即抛错（敏感值禁止暴露到浏览器，任何模式均禁止，对应 auth spec FR-024）；mock 模式 `SSO_CLIENT_SECRET` 可缺省
- 默认值（模块内常量）：`DEFAULT_SSO_SCOPE='openid profile email groups offline_access'`、`DEFAULT_ID_TOKEN_VERIFY_MODE='strict'`、`DEFAULT_SSO_REFRESH_TOKEN_MAX_AGE_DAYS=30`、`DEFAULT_SSO_RETRY_MAX=3`
- 测试补充 mock 环境分支与敏感变量拒绝用例

## 配置 / 环境变量变化

| 变量名 | 默认值 | 说明 |
|--------|--------|------|
| `SSO_CLIENT_SECRET` | 无 | 服务端 client_secret（mock 可缺省；仅 Node 层引用） |
| `SSO_ISSUER` | 无 | 服务端 issuer（Discovery/iss 校验契约，mock 必填） |
| `SSO_CLIENT_ID` | 无 | 服务端 client_id（Node 侧权威） |
| `ID_TOKEN_VERIFY_MODE` | `strict` | id_token 验证模式：`strict` 拒登 / `soft` 记日志 |
| `SSO_REFRESH_TOKEN_MAX_AGE_DAYS` | `30` | refresh_token cookie 持久化天数 |
| `SSO_MOCK_ENABLED` | `0` | mock IDP 开关（测试/联调环境） |
| `SSO_RETRY_MAX` | `3` | IDP 调用重试上限 |
| `SSO_SCOPE` / `SSO_ISSUER_PUBLIC` 等（NEXT_PUBLIC_*） | 见 getSsoEnv | 浏览器可见配置 |
| `NEXT_PUBLIC_SSO_CLIENT_SECRET` | 禁止存在 | 存在即 validateEnv 抛错 |
