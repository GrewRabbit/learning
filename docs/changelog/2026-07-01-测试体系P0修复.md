# 测试体系 P0 级问题修复

**日期**：2026-07-01
**类型**：新增
**影响范围**：测试基础设施（单元测试覆盖率度量 / 集成测试 / CI/CD 流水线）

## 变更背景

测试评估发现三项 P0 级问题：
1. **覆盖率不可度量**：未配置 coverage 工具，无法量化代码行/分支覆盖率
2. **集成测试缺失**：`tests/integration-tests/` 目录不存在，且 vitest.config.ts 的 include 路径与 testing-standards.md 规范不一致
3. **无 CI/CD 自动化**：无 GitHub Actions 流水线，测试无自动门禁，违反 cicd-workflow.md 规范

本次修复建立测试度量基线、补全集成测试层、接入 CI 自动化。

## 变更内容

### P0-1：覆盖率工具配置

- 安装 `@vitest/coverage-v8` devDependency
- vitest.config.ts 添加 coverage 配置（provider: v8，reporter: text/text-summary/html）
- 度量范围限定 `app/lib/**` 与 `app/api/**`，排除测试文件/类型/配置/prompts/data
- **不设硬性阈值门禁**：先建立基线，待基线稳定后再设门禁阈值
- 新增 `npm run test:coverage` 脚本
- .gitignore 排除 `/coverage/`

### P0-2：集成测试基线

- 修正 vitest.config.ts include 路径：`tests/integration/**/*.test.ts` → `tests/integration-tests/**/*.test.ts`（与 testing-standards.md §三 一致）
- 新增 `tests/integration-tests/orchestrator.test.ts`（7 个用例）
- 集成测试策略：mock LLM/ImageRecognizer/fetchProblem，保留真实 HtmlParser + CodeValidator（真实 g++ 编译）+ HtmlCache（真实内存 LRU）
- 覆盖场景：text 完整链路、修正循环、内容缓存命中、platform 完整链路 + 主 key 回填、LLM 格式错误降级

### P0-3：CI/CD 流水线

- 新增 `.github/workflows/pr-check.yml`：PR 触发，type-check + lint + 单元测试 + 构建验证（遵循 cicd-workflow.md §二，不含 E2E）
- 新增 `.github/workflows/deploy.yml`：合并 main 触发，构建 + @critical E2E（依赖 LLM API secrets）
- playwright.config.ts 启用 webServer（reuseExistingServer: true）：本地复用已运行 dev server，CI 自动启动

## 后续影响 / 注意事项

1. **集成测试依赖 g++**：CI 环境（ubuntu-latest）自带 g++，无需额外安装；本地需确保 g++ 可用
2. **fs/promises partial mock**：集成测试中 `vi.mock('fs/promises')` 必须用 `importOriginal` 保留 `mkdtemp/rm/writeFile`，否则真实 CodeValidator 文件操作失效
3. **Playwright webServer 启用**：本地跑 E2E 时若 dev server 已运行则复用（行为不变），未运行则自动启动
4. **CI secrets 待配置**：部署流水线 E2E 需在 GitHub 仓库 Settings → Secrets 配置 LLM 环境变量，否则 @critical E2E 会因环境变量缺失失败
5. **覆盖率阈值未设**：当前仅生成报告，待基线稳定后可在 vitest.config.ts 添加 `thresholds`（建议 lines/branches ≥ 80%）
6. **低覆盖项**（后续 P1 优化）：`fs-html-cache.ts`(11.49%)、`config.ts`(7.69%)、`llm-client.ts`(0%)、`logger.ts`(0%)、`env.ts`(40.35%)、`api/health/route.ts`(0%)
