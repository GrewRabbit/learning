# E2E 契约测试 SSO 认证适配

**日期**：2026-08-10
**类型**：修复
**影响范围**：tests/e2e-tests（Playwright 配置、契约测试、SSO 登录测试）

## 变更背景

SSO 实施步骤 8（`app/lib/auth/guard.ts` + middleware 粗检）后，`/api/solve` 成为受保护资源：未认证请求被 middleware 302 到 `/login` 并返回 HTML。原 18 个 `@fast @no-llm` 契约测试（api-contract 14 个、platform-input 2 个、validation 2 个）直接以匿名身份 POST `/api/solve`，收到 HTML 而非 JSON，全部失败。需为这些测试提供认证会话。

## 变更内容

### Playwright 认证模式（官方 storageState setup 模式）

- 新增 `tests/e2e-tests/helpers/sso-login.ts`：从 `sso-login.spec.ts` 抽取的共享登录 helper（`startAuthorize` / `loginAndConsent` / `ssoLogin`），供流程测试与 setup 复用
- 新增 `tests/e2e-tests/auth.setup.ts`：SSO 真实登录一次并保存 `storageState` 到 `tests/e2e-tests/.auth/sso-user.json`
- `playwright.config.ts` 增加 `setup` 项目（运行 auth.setup.ts）与 `chromium-auth` 项目（`dependencies: ['setup']` + `use.storageState`），仅匹配需要认证的三个 spec 文件；`chromium` 项目通过 `testIgnore` 排除这些 spec
- `api-contract.spec.ts`：全部 14 个测试由 `request` fixture（隔离 cookie jar）改用 `page.request`（共享浏览器上下文 cookie），从而携带 setup 会话
- `.gitignore` 排除 `/tests/e2e-tests/.auth/`
