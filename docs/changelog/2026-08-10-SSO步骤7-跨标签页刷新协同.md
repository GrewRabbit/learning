# SSO 步骤7：跨标签页刷新协同（refresh-sync）

**日期**：2026-08-10
**类型**：新增
**影响范围**：`app/lib/sso/refresh-sync.ts`（模块 M4，浏览器侧工具）；登录/续期客户端流程（步骤 6 token-refresher 跨标签页协同）

## 变更背景

实施 SSO 集成步骤 7（架构 §11 步骤 7 / 模块 M4，AD-13 / AR2-003）：跨标签页并发刷新协同。httpOnly cookie 跨标签页共享但各标签页 JS 上下文独立，多标签页同时用同一旧 refresh_token 并发刷新会触发 IDP 重放检测并撤销用户全部会话（token spec FR-005 / OQ-05，风险等级高）。落地候选①：localStorage 锁 + BroadcastChannel 广播（架构 §9.3 裁决）。

## 变更内容

### `app/lib/sso/refresh-sync.ts`（新 M4 浏览器侧工具模块，'use client'）

- 常量：`REFRESH_TOKEN_SESSION_KEY='sso_refresh_token'`、`REFRESH_BROADCAST_CHANNEL='sso_refresh_sync'`、`REFRESH_BROADCAST_SIGNAL='sso-refresh-occurred'`
- 函数：
  - `getSsoRefreshToken(): string | null`——sessionStorage 镜像优先；无值且存在同名非 httpOnly cookie 时镜像写入并返回；均无 → null（httpOnly 通道 document.cookie 读不到，服务端为权威）
  - `setSsoRefreshToken(token): void`、`clearSsoRefreshToken(): void`——sessionStorage 镜像读写清
  - `notifyRefreshOccurred(): void`——BroadcastChannel 广播「刷新完成」信号
  - `subscribeRefreshSignal(callback): () => void`——订阅信号，返回取消订阅函数
- **关键裁决（AR2-003）**：广播**仅发字符串信号、不传 token**（JS 无法写 httpOnly cookie）；他标签页收到信号后自行调 `/api/sso/refresh`（服务端 Set-Cookie 回写）或清 sessionStorage + 提示重登
- 运行分层：纯浏览器 Web API（window/sessionStorage/document/BroadcastChannel），无 Node 依赖；非浏览器环境（SSR/测试 node）下全部函数安全降级为 no-op / 返回 null，不抛错
- 日志脱敏（FR-026）：本模块不落日志，token 值仅存在于 sessionStorage 内存通道

### 测试（`app/lib/sso/__tests__/refresh-sync.test.ts`，14 例）

- sessionStorage 读写清镜像、cookie 兜底镜像（含 httpOnly 读不到场景）、BroadcastChannel 信号收发与退订、非浏览器环境降级不抛错
