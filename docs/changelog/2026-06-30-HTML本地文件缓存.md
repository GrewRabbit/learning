# HTML 本地文件缓存（FsHtmlCache）

**日期**：2026-06-30
**类型**：新增
**影响范围**：`app/lib/ai/services/` 缓存层、环境变量配置、`.gitignore`、规则体系

## 变更背景

原有 `DualKeyHtmlCache` 是纯内存 LRU 缓存（`max: 100`，`ttl: 1h`），HTML **不落盘**。这带来两个问题：

1. **调试困难**：用户反馈"流程图/思维导图渲染不正常"，但因 HTML 只存在于内存与浏览器 sessionStorage，无法直接 `cat` 文件查看 LLM 实际输出，难以定位是 LLM 输出问题还是渲染问题
2. **重启即丢**：Next.js 进程重启后缓存清空，相同题目需重新调用 LLM（成本与时间）

本次变更新增文件系统持久化实现 `FsHtmlCache`，通过环境变量切换，**默认仍为内存模式**（向后兼容），调试期开启 fs 模式即可将 LLM 生成的 HTML 落盘到本地文件，便于直接查看与排查。

同时新增"更新日志规范"规则，定义何时需要为变更写更新日志。

## 变更内容

### 新增 FsHtmlCache 实现

- 新建 `app/lib/ai/services/fs-html-cache.ts`，实现 `HtmlCache` 接口（与 `DualKeyHtmlCache` 同接口）
- 目录结构：
  ```
  {baseDir}/
    primary/{platform}_{problemId}.json   → PrimaryIndex { contentHash, createdAt }
    content/{hash前2位}/{hash}.html        → HTML 文件（LLM 原始输出）
    content/{hash前2位}/{hash}.json        → SolutionMeta { validated, warning, createdAt }
  ```
- 读操作同步（`fs.readFileSync`，单文件 1-5ms 可接受，匹配接口同步签名）
- 写操作 fire-and-forget 异步（不阻塞响应，符合架构 §4.4 写入失败仅记日志不阻断）
- 文件不存在/损坏 → 返回 `null`（视为缓存未命中，触发 LLM 重新生成）
- 单飞机制（in-flight Promise Map）保留，与 `DualKeyHtmlCache` 一致
- 内容 key 文件分桶（`{hash前2位}/`）避免单目录文件爆炸

### 缓存驱动切换

- 修改 `app/lib/ai/services/html-cache.ts` 末尾单例导出，改为根据环境变量动态选择实现：
  - `GESP6_CACHE_DRIVER=fs` → 启用 `FsHtmlCache`
  - 其他/未设置 → 默认 `DualKeyHtmlCache`（向后兼容）
- Orchestrator 完全无感知（依赖 `HtmlCache` interface，符合架构 §5.1 接口抽象）

### .gitignore 调整

- 添加 `/data/` 忽略（FsHtmlCache 默认缓存目录 `/var/learning/data/gesp6` 在项目内）

## 后续影响 / 注意事项

### 启用方式

在 `.env.local` 中添加（**不要**提交到 git）：

```bash
GESP6_CACHE_DRIVER=fs
# 可选：覆盖默认缓存目录
# GESP6_CACHE_FS_DIR=/var/learning/data/gesp6
```

或开发期临时启用：

```bash
GESP6_CACHE_DRIVER=fs npm run dev
```

### 调试期查看 LLM 实际输出

启用 fs 模式后，提交题目即可在文件系统中查看：

```bash
# 查看所有缓存的 HTML 文件
ls /var/learning/data/gesp6/content/*/

# 查看某个 HTML（直接浏览器打开或 cat）
cat /var/learning/data/gesp6/content/ab/abcdef123....html

# 查看主 key 索引（platform + problemId → contentHash）
cat /var/learning/data/gesp6/primary/luogu_P15800.json
```

### 注意事项

1. **默认仍是 memory 模式**：未设置环境变量时行为完全不变，单元测试与现有部署不受影响
2. **缓存不自动清理**：fs 模式无 TTL，需手动清理或加 cron 定时任务（按 `mtime` 清理过期文件）
3. **单机部署限制**：fs 模式仅在单机 Next.js 进程下生效；多机部署需切换到未来的 `DbHtmlCache`
4. **不存 meta（code/samples）**：当前 `Solution` 类型不含 meta 字段，FsHtmlCache 仅持久化 `html` + `validated` + `warning`；如需完整持久化（含可执行 code），需扩展 `Solution` 类型（未来数据库方案中规划）
5. **`/data` 在容器内可能只读**：本次实施时发现 `/data` 在当前环境为只读文件系统，已将默认路径改为项目内 `/var/learning/data/gesp6`，可通过 `GESP6_CACHE_FS_DIR` 覆盖

### 与原稿 skill 的关系

本次变更**不影响** `app/lib/ai/prompts/gesp6-skill.md` 与 `.trae/skills/gesp6-solution/SKILL.md`，因为：
- LLM 输出格式（`<<<META>>>` + `<<<HTML>>>`）不变
- Orchestrator 调用 HtmlCache 的方式不变
- 缓存层对 LLM 完全透明

### 后续规划

- **多解法数据库存储**：本次 fs 持久化是过渡方案，未来上 SQLite/PostgreSQL 后切换到 `DbHtmlCache`（同样实现 `HtmlCache` 接口，Orchestrator 无需改动）
- **多解法支持**：需要扩展 `Solution` 类型为 `solutions: Solution[]`，每个解法有独立 `solutionKey`，并在 `/result` 页面加 Tab 切换
