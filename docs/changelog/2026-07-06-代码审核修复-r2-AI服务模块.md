# 代码审核 r2 修复 - AI 服务模块

**日期**：2026-07-06
**类型**：优化
**影响范围**：`app/lib/ai/types.ts`、`app/lib/ai/services/llm-caller.ts`、`app/lib/ai/services/fix-loop.ts`（共 3 个文件）

## 变更背景

第 2 轮全量代码审核（[code-review-full-r2.md](../reviews/code-review-full-r2.md)）针对 AI 服务模块新发现 6 个问题，本 agent 分配到其中 4 个（CR2-001/002/003/006），均为类型安全、可维护性与文档一致性范畴。本次按审核意见逐条修复，与 CR1-015（llm-client.ts ChatMessage 联合类型）修复模式保持一致，进一步消除类型逃逸。

核心驱动：
- **类型安全**：消除 `as OpenAI.Chat.Completions.ChatCompletionMessageParam[]` 单重类型断言，从源头收窄 `LLMInput.history.role` 类型
- **可维护性**：将 fix-loop.ts 日志前缀与模块名对齐，避免排障误导
- **文档一致性**：核对 r1 changelog 中 fix-loop.ts 记录情况

## 变更内容

### CR2-002 + CR2-001：history.role 联合类型 + 移除 as 断言（联动修复）

按 CR2-001 修订建议方案 (1) 与 CR2-002 联动修复：

- **CR2-002**：将 [types.ts:79](../../app/lib/ai/types.ts#L79) 的 `history?: Array<{ role: string; content: string }>` 改为联合类型 `history?: Array<{ role: 'system' | 'user' | 'assistant'; content: string }>`，与 CR1-015 修复 llm-client.ts ChatMessage 的 discriminated union 模式一致
- **CR2-001**：修复 [llm-caller.ts:188-195](../../app/lib/ai/services/llm-caller.ts#L188-L195) 的 messages 构造，移除 `as OpenAI.Chat.Completions.ChatCompletionMessageParam[]` 单重类型断言。CR2-002 收窄后，history 元素 `{ role, content }` 的 role 字面量类型与 `ChatCompletionMessageParam` 联合成员按字面量匹配，可直接展开赋值，无需类型逃逸

### CR2-006：fix-loop.ts 日志前缀改为 [FixLoop]

- 将 [fix-loop.ts](../../app/lib/ai/services/fix-loop.ts) 内 7 处日志前缀 `[Orchestrator.compute]` 机械替换为 `[FixLoop]`：
  - 第 75 行 `[FixLoop] 进入修正循环`
  - 第 81 行 `[FixLoop] 检测到取消标记，中止修正循环`
  - 第 107 行 `[FixLoop] 修正调用完成`
  - 第 129 行 `[FixLoop] 修正输出解析失败，降级返回`
  - 第 154 行 `[FixLoop] 修正后重新验证`
  - 第 177 行 `[FixLoop] 修正后验证通过`
  - 第 189 行 `[FixLoop] 3 次修正后仍未通过`
- 日志前缀与 fix-loop.ts 模块名一致，排障时可直接定位到 fix-loop.ts，不再误导至 orchestrator.ts
- 注：orchestrator.ts 内的 `[Orchestrator.compute]` 日志前缀属于 orchestrator 模块本身，不在本次修复范围内

**核实结论**：r1 changelog 已实质记录 fix-loop.ts 的创建，CR2-003 描述中"未列入 r1 修订对照表"指 reviewer 比对的非 changelog 文档（如 code-review-full-r1-response.md 等）。r1 changelog 实际包含以下 5 处 fix-loop.ts 记录：
