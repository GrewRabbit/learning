# SSO 步骤6：令牌刷新模块 M3（token-refresher + /api/sso/refresh）

**日期**：2026-08-10
**类型**：新增
**影响范围**：`/api/sso/refresh` 路由；`app/lib/sso/token-refresher.ts`（模块 M3）；步骤 8 requireAuth 将复用本模块

## 变更背景

实施 SSO 集成步骤 6（架构 §11 步骤 6 / 模块 M3）：access_token 的按需续期服务层与刷新端点。授权码登录（步骤 5）签发的 access_token 仅 15 分钟有效，需在剩余有效期 <60s 时用 refresh_token 静默续期（token spec FR-004~FR-010），避免用户频繁重登。本步骤完成服务端单飞刷新核心与 HTTP 刷新端点（M1 的刷新部分），前端刷新调度（M4）与 requireAuth 触发（步骤 8）复用本模块。

## 变更内容

### `app/lib/sso/token-refresher.ts`（新服务层模块 M3）

- 导出 `class TokenRefresher`（构造可注入 `{ fetchFn?, now? }`，now 为可控时钟供测试）+ 单例 `export const tokenRefresher`
- `refreshIfNeeded(request: NextRequest): Promise<ServiceResult<TokenResponse>>`
  - 读取请求 cookie 的 refresh_token/access_token（FR-003 语义：无 refresh_token → `AUTH_SESSION_INVALID`，不调用 IDP）
  - 触发判定（FR-004）：本地 base64url 解码 access_token 的 `exp`，剩余 <60s（`REFRESH_THRESHOLD_SECONDS=60`）才刷新；剩余 ≥60s 返回 `{success:true}`（无 data）；access_token 缺失/无法解码视为需刷新（恢复路径）
  - 单飞（FR-005）：inflight Map（key=refresh_token 值），同值并发仅发起一次 IDP 请求，其余复用同一 Promise；完成后自动释放
  - 轮换（FR-006/007）：`oauthClient.refreshToken({refresh_token})`；成功透传新 TokenResponse（含新 access/refresh_token），旧 refresh_token 不再使用；cookie 回写由路由层负责
  - 分类处置（FR-010）：invalid_grant 透传 `AUTH_INVALID_GRANT`（不重试）；invalid_client → 记配置错误日志（不重试）；429/5xx/网络重试已在 oauth-client 内部完成，本层不重复，其余失败透传（429 → `AUTH_IDP_RATE_LIMITED`、网络 → `AUTH_IDP_UNREACHABLE` 等）；意外异常兜底 `AUTH_REFRESH_FAILED`
- `onInvalidGrant(response: NextResponse): Promise<ServiceResult<void>>`（FR-009）：清 access/refresh/id_token 三个 cookie（maxAge=0）+ 安全告警日志（含 `AUTH_INVALID_GRANT`，不含 token 明文，FR-022）

### `/api/sso/refresh`（POST 刷新端点，架构 §5.3 M1）

- 仅 POST（GET 405 `METHOD_NOT_ALLOWED`，与 authorize 端点一致）
- 调用 `tokenRefresher.refreshIfNeeded(request)`；成功回写 `setSessionCookies`：refresh_token 替换（30 天）+ access_token 覆盖（maxAge 按新 `expires_in` 重置，FR-006）；id_token 保持请求中的原值（FR-008：刷新响应不返回 id_token，不更新）
- 错误映射：无 refresh_token → 401 `AUTH_SESSION_INVALID`；invalid_grant → `onInvalidGrant` 清 cookie + 401 `AUTH_INVALID_GRANT`（引导重新登录）；429 → 429 `AUTH_IDP_RATE_LIMITED`；IDP 不可达 → 502 `AUTH_IDP_UNREACHABLE`；其他 → 500 `AUTH_REFRESH_FAILED`（文案安全通用，FR-026）
- 错误 envelope `{success:false, error:{code,message}}`；成功 `{success:true, data:{}}`

## 后续影响 / 注意事项

- 步骤 8 `requireAuth` 复用 `tokenRefresher.refreshIfNeeded()` 做同步续期；M4 前端刷新调度（步骤 7）中同源标签页收到信号后调本端点主动回写 cookie
- 刷新端点成功回写依赖 `setSessionCookies`，id_token 沿用请求 cookie 原值（刷新响应无 id_token）；若请求无 id_token cookie 则以空串回写（实践中登录必定三 cookie 同写，不影响）
- oauth-client 对刷新响应仍要求 `id_token` 字段存在（否则 `AUTH_TOKEN_EXCHANGE_FAILED`）；若 IDP 刷新响应确不返回 id_token，属步骤 3 遗留约束，需后续评估放宽
