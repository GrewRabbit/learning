# Next.js 错误处理约定文件与 middleware 单元测试

**日期**：2026-07-01
**类型**：新增
**影响范围**：app/error.tsx、app/global-error.tsx、app/not-found.tsx、__tests__/middleware.test.ts

## 变更背景

P0 评估报告（Next.js 最佳实践维度）指出项目缺失以下 Next.js 约定文件：

1. **app/error.tsx**：路由段错误边界（Server/Client Component 渲染异常时显示）
2. **app/global-error.tsx**：根 layout 错误边界（root layout 自身崩溃时接管）
3. **app/not-found.tsx**：自定义 404 页面（访问不存在路由时显示项目主题页）

此前 LLM 调用失败、Orchestrator 抛错、访问 `/foo` 等不存在路径均显示 Next.js 默认错误页，与项目主题不符，用户体验差。

同时 `middleware.ts` 实现 IP 限流（5 次/分钟/IP），但**完全没有单元测试**，仅通过 E2E 测试注入唯一 `x-forwarded-for` 绕过限流逻辑，限流阈值、IP 提取、健康检查豁免等关键路径无回归保护。

## 变更内容

### Next.js 错误处理约定文件

新增 3 个 Next.js 约定文件（遵循 next-best-practices error-handling.md）：

#### app/error.tsx

- 类型：Client Component（Next.js 约定）
- 触发场景：Server/Client Component 渲染抛错、未捕获 Promise rejection
- 行为：显示"页面出错了"提示 + 错误编号（digest）+ 重试按钮 + 返回首页
- 错误日志：`useEffect` 中调用 `console.error('[route-error]', ...)` 记录错误上下文

#### app/global-error.tsx

- 类型：Client Component（Next.js 约定）
- 触发场景：root layout.tsx 自身崩溃、全局 Provider 抛错
- 行为：显示"应用发生严重错误"+ 重试按钮
- 关键约束：自带 `<html><body>` 标签 + 内联样式（不依赖 globals.css，因 root layout 加载失败时 CSS 可能也加载失败）

#### app/not-found.tsx

- 类型：Server Component（无需 'use client'）
- 触发场景：访问不存在路由、Server Component 调用 `notFound()`（当前项目未使用，预留）
- 行为：显示 404 + "页面不存在" + 返回首页链接（使用 `next/link`）

### middleware 单元测试

新增 `__tests__/middleware.test.ts`（12 用例），覆盖：

| 维度 | 用例数 | 覆盖点 |
|------|--------|--------|
| /api/health 豁免 | 2 | 单次放行、连续 20 次仍放行 |
| 限流逻辑 | 3 | 5 次内放行、第 6 次 429 GESP6_RATE_LIMITED、不同 IP 独立计数 |
| IP 提取 | 5 | x-forwarded-for 多 IP 取首段、单 IP、x-real-ip 回退、无 IP 头 unknown、xff 优先级高于 x-real-ip |
| 非 /api/* 路径 | 1 | 页面路径也经过 middleware 函数（matcher 在 config 控制） |
| config 导出 | 1 | matcher 仅匹配 `/api/:path*` |

测试策略：

- mock `next/server` 的 `NextResponse.json` 与 `NextResponse.next`（使用 `vi.hoisted` 提升 mock 变量避免 vi.mock 工厂引用未初始化顶层变量）
- 用唯一 IP（`10.0.0.{seq}`）隔离用例，避免模块级 `ipRequestMap` 状态污染
- 通过 `middleware` 函数间接覆盖 `pruneExpiredTimestamps` + `getClientIp` 内部逻辑（这两个函数未 export）

## 后续影响 / 注意事项

1. **error.tsx 不捕获 root layout 错误**：root layout 崩溃由 global-error.tsx 接管，二者职责分离
2. **error.tsx / global-error.tsx 必须为 Client Component**：Next.js 硬性约定，不可改为 Server Component
3. **global-error.tsx 不依赖 globals.css**：使用内联样式兜底，确保 root layout 加载失败时仍可渲染
4. **middleware 单元测试与 coverage 配置**：`__tests__/middleware.test.ts` 在项目根目录，vitest.config.ts 的 coverage include 范围（`app/lib/**/*.ts` + `app/api/**/*.ts`）不覆盖 middleware.ts。若需覆盖率统计，需扩展 include 范围（当前选择不扩展，因 middleware 是基础设施层而非业务逻辑）
5. **E2E 测试与 middleware 单元测试的关系**：E2E 通过 `x-forwarded-for` 注入唯一 IP 绕过限流（避免限流干扰测试），middleware 单元测试正面验证限流逻辑本身，二者互补不重复
