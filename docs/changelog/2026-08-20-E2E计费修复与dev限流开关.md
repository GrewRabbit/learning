# E2E 计费修复与 dev 限流开关

**日期**：2026-08-20
**类型**：修复
**影响范围**：`tests/e2e-tests/specs/billing.spec.ts`、`tests/e2e-tests/helpers/sso-login.ts`、`tests/e2e-tests/helpers/billing-db.ts`（新增）、`tests/e2e-tests/auth.setup.ts`、`scripts/dev.mjs`（新增）、`package.json`

## 变更背景

本轮处理两个问题：

1. **E2E 计费用例批量失败**：billing.spec 全部用例因 strict mode violation 失败——`billingBanner()` 定位器 `[role="status"]:not(#__next-route-announcer__)` 同时匹配到真实计费横幅与 Next.js 15 dev 模式的 "Static route" 指示 toast（`.nextjs-toast`，同为 `role="status"`），Playwright strict mode 报错。修复后进一步暴露出两个被掩盖的次级问题：AC-013 用例断言 a0000000 首次提交「本次已计费」，但测试 1/2 已建立 access（实为「本次免费」）；以及 a0000003 首次登录必现的 IDP consent 页为中文 locale（按钮「允许」），helper 只匹配英文 'Allow' 导致登录失败、用例 skip。
2. **计费测试余额管理**：整轮 E2E 中 `@llm` 解题用例会真实扣费，若共享账户 a0000000 余额不足会在中途因余额不足中断；同时缺少「余额不足」的端到端前端反馈链路用例（仅单测/集成覆盖）。另 `npm run dev` 无法便捷关闭中间件限流（20 次/分/IP），手动起服务跑 E2E 会假失败。

## 变更内容

### E2E 计费用例修复（billing.spec.ts + sso-login.ts）

- `billingBanner()` 定位器排除 Next.js dev 指示 toast（`:not(.nextjs-toast)`），消除 strict mode 二义性
- AC-013 用例前置自行 `resetTestAccount('a0000000')`，清除测试 1/2 已建立的 access，使首次提交确为「本次已计费」且用例可独立单跑；同步更新文件头串行依赖注释
- `sso-login.ts` consent 按钮点击改为正则 `/Allow|允许|同意|授权/i`，覆盖 IDP 多 locale（en/zh-CN），修复 a0000003 首次登录必现 consent 时登录失败

### dev 限流开关（scripts/dev.mjs + package.json）

- 新增 `scripts/dev.mjs` 启动器：参数透传给 `next dev`，支持 `--test` 标志关闭中间件限流（设置 `GESP6_RATE_LIMIT_ENABLED=0` + `GESP6_RATE_LIMIT_MAX=100000`），等价 `npm run dev:test`
- `dev` / `dev:test` 脚本统一走该启动器（单一来源）；`npm run dev -- --test` 即可一键进入测试模式

### 计费余额管理（billing-db.ts + auth.setup.ts + billing.spec.ts）

- 新增 `tests/e2e-tests/helpers/billing-db.ts`：`setBalance(sub, 余额)` 精确设置免费额度（无 quota 行则插入，fail-soft 返回 false）、`clearUserAccess(sub)` 清空已获取访问记录；供「余额充足防中断」与「余额不足触发」两类场景使用
- `auth.setup.ts` 每轮运行前将共享账户 a0000000 余额置为 1000（fail-soft，DB 不可用不阻断登录），保证整轮 chromium-auth 用例余额充足
- `billing.spec.ts` 重置额度由 5 改为 1000（各用例只断言「本次已计费/免费」与「剩余额度」文案、不校验具体数值），避免本 spec 耗尽共享账户额度导致同轮后续 `@llm` 用例中断

### 新增「余额不足」E2E 用例（billing.spec.ts）

- `@no-llm` 用例：清 a0000000 access + 余额置 0 → 提交已缓存 B2002（缓存命中不调 LLM）→ 首次计费扣费不足 → 前端停留 /solve 并展示「余额不足」错误、不返回解法（FR-019 / AC-016 前端反馈链路）
- 用例置于文件末尾，`afterAll` 恢复 a0000000 余额为 1000，不影响本文件其余用例与同轮后续 `@llm` 解题用例

## 后续影响 / 注意事项

- 手动跑 E2E 起服务方式不变（`npm run dev:test`），新增等价入口 `npm run dev -- --test`
- 调试过程中发现 dev server 长时间运行后路由清单可能损坏（`/api/sso/authorize` 404），重启 dev server 可恢复
- 余额不足用例依赖 B2002 已缓存（文件头既有假设，缓存命中不调 LLM）；若缓存被清理该用例会退化为走 LLM 后触发余额不足（耗时变长但仍可断言通过）
