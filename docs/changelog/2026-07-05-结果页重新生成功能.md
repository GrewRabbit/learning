# 结果页"重新生成"功能

**日期**：2026-07-05
**类型**：新增
**影响范围**：结果页（result/page.tsx）、输入页（solve/page.tsx）、API 路由（api/solve/route.ts）、Orchestrator 编排层、HtmlCache 缓存层（DualKeyHtmlCache + FsHtmlCache）

## 变更背景

/result 页原有"重新生成"按钮实际只跳转回 /solve（无预填、无重新提交），名称与行为不符。用户需要：对同一题目强制重新提交给大模型生成新解法，并更新缓存映射关系（primary key → contentHash、sample fingerprint → contentHash）。

## 变更内容

### 1. 按钮语义澄清（result/page.tsx）

- 原"重新生成"按钮重命名为"返回"（仅跳转 /solve，无重新提交语义）
- 新增"重新生成"按钮 → 跳转 `/solve?regenerate=true`，触发自动重新提交流程

### 2. 原始 Problem 持久化（types.ts + solve/page.tsx）

- **types.ts**：新增 `PROBLEM_STORAGE_KEY = 'gesp6:problem'` 常量
- **solve/page.tsx**：
  - 新增 `submittedProblemRef` 跟踪当前提交的 Problem
  - `handleSubmit` 重构：接受可选 `(explicitProblem?, regenerate?)` 参数，支持自动提交模式
  - job 完成时将原始 Problem 写入 sessionStorage（供 /result 页"重新生成"读取）
  - 图片输入的 base64 可能超出 sessionStorage 配额，try-catch 静默失败（不影响主流程）

### 3. ?regenerate=true 自动提交（solve/page.tsx）

- 新增 useEffect 检测 URL 参数 `?regenerate=true`
- 从 sessionStorage 读取原始 Problem，预填表单（text/image/platform），自动调用 `handleSubmit(problem, true)`
- 读取失败时提示"未找到原题目数据，请重新输入"

### 4. API 层 regenerate 标志（route.ts）

- POST schema 新增 `regenerate: z.boolean().optional()` 字段
- 透传 `forceRegenerate` 布尔值给 `orchestrator.solve()` 第 4 参数
- 日志增加 `regenerate` 字段

### 5. Orchestrator 强制重新生成路径（orchestrator.ts）

- `solve()` / `solvePlatform()` / `solveTextOrImage()` 新增 `forceRegenerate?: boolean` 参数
- **solvePlatform**：`forceRegenerate=true` 时跳过主 key 前置检查（不读 primaryCache）
- 透传 `forceRegenerate` 给 `cache.getOrCompute()` 第 4 参数

### 6. 缓存层 forceRegenerate 支持（html-cache.ts + fs-html-cache.ts）

- `HtmlCache.getOrCompute()` 接口新增 `forceRegenerate?: boolean` 参数
- **DualKeyHtmlCache**：`forceRegenerate=true` 时跳过步骤 1-3（content 读、sample 读、in-flight 复用），直接走 compute + 缓存写
- **FsHtmlCache**：同上，跳过文件系统缓存读，compute 后覆盖 content 文件 + sample 索引文件
- 缓存写逻辑保持不变：compute 成功后覆盖 contentCache/content 文件，validated=true 时覆盖 sampleCache/sample 索引

### 缓存映射更新机制

contentHash 基于输入内容计算（非输出），同一题目重新生成时 contentHash 不变，缓存映射关系如下更新：

| 映射 | 更新方式 |
|------|---------|
| primary key → contentHash | solvePlatform 中 `cache.set(primaryKey, contentHash, newSolution)` 覆盖 |
| contentHash → HTML content | getOrCompute 内部 `contentCache.set` / `writeContentFiles` 覆盖 |
| sampleFp → contentHash | getOrCompute 内部 `sampleCache.set` / `writeSampleIndex` 覆盖（仅 validated=true） |

## 后续影响 / 注意事项

1. **图片输入重新生成的限制**：图片 base64 可能超出 sessionStorage 配额（5-10MB），写入失败时 /result 页"重新生成"会提示"未找到原题目数据，请重新输入"。大图片场景需重新上传
2. **forceRegenerate 跳过 in-flight 复用**：并发重新生成同一题目会产生多次 LLM 调用（不做去重），写入时覆盖同一 contentHash 的缓存（最终一致性）
3. **缓存覆盖语义**：重新生成后，旧缓存被新 HTML 覆盖。若新结果 validated=false 而 sample 索引已存在（指向同 contentHash），sample 索引不会被清理（保持指向，但 content 已更新为未验证版本）
4. **sessionStorage 生命周期**：PROBLEM_STORAGE_KEY 与 SOLUTION_STORAGE_KEY 同生命周期，关闭标签页后清除。用户刷新 /result 页仍可读取（同一标签页会话）
5. **?regenerate=true 直接访问**：用户手动输入该 URL 时，若无 sessionStorage 中的 Problem 数据，会显示"未找到原题目数据"提示，不会崩溃
