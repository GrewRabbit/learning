# 移动端轮询与 MIME 修复

**日期**：2026-07-02
**类型**：新增 + 修复
**影响范围**：API 接入层（/api/solve）、题目录入页（/solve）、LLM 调用层（llm-caller）、Next.js 配置（next.config.ts）

## 变更背景

移动端浏览器（iOS Safari / Chrome Android）对长连接 fetch 有严格超时限制（约 60-300 秒）。系统解题流程通常需要 3-5 分钟（图片识别 30-60s + LLM 生成 60-120s + 编译验证 5-10s + 修正循环最多 3 轮），导致移动端提交后连接被浏览器提前中断，前端无法接收到结果，用户被跳回输入页。

同时发现两个相关缺陷：
1. 移动端拍摄的 PNG 图片提交时，`llm-caller.ts` 硬编码 `data:image/jpeg` MIME 前缀，导致 LLM API 400 错误。
2. 拍照上传按钮无法打开摄像头，因 `next.config.ts` 中 `Permissions-Policy: camera=()` 禁用了所有来源。

## 变更内容

### 任务队列与轮询（新增）

- **新增 `app/lib/job-store.ts`**：内存任务队列，模块级 `Map<string, JobRecord>` 单例，30 分钟 TTL，每 5 分钟节流清理一次。提供 `createJob()` / `completeJob()` / `failJob()` / `getJob()` 四个原子操作，使用 `crypto.randomUUID()` 生成 jobId。
- **改造 `app/api/solve/route.ts`**：
  - POST 不再 `await orchestrator.solve()`，改为 `createJob()` 后立即在后台启动 `.then()/.catch()` 链，并返回 `{ success: true, data: { jobId } }`。响应时间从分钟级降到毫秒级。
  - 新增 GET handler：解析 `jobId` query 参数，查询任务状态返回 `processing` / `done` + `Solution` / `error`，不存在的 jobId 返回 404 `GESP6_JOB_NOT_FOUND`。
- **改造 `app/solve/page.tsx`**：
  - `handleSubmit` 改为两步：先 POST 获取 jobId，再调用 `pollJob(jobId)` 递归轮询。
  - 轮询参数：间隔 3 秒（网络错误延迟 6 秒），客户端超时 10 分钟。
  - 新增进度展示：`Loader2` 旋转图标 + 实时耗时显示"AI 正在解题中，请耐心等待...（已等待 X分Y秒）"。
  - 新增"取消"按钮，停止轮询并复位状态。
  - 组件卸载时通过 `useEffect` 清理 `setTimeout` 与 `setInterval`，使用 `pollingRef` 标志位防止内存泄漏。

### 图片 MIME 自动识别（修复）

- **`app/lib/ai/services/llm-caller.ts`**：新增 `detectImageMime(base64)` 函数，根据 base64 magic bytes 自动识别格式：
  - `iVBORw0KGgo` → `image/png`
  - `/9j/` → `image/jpeg`
  - `R0lGOD` → `image/gif`
  - `UklGR` → `image/webp`
  - 兜底 → `image/jpeg`
- `image_url` 构造从硬编码 `image/jpeg` 改为 `detectImageMime(input.problem.content)`。

### 摄像头权限（修复）

- **`next.config.ts`**：`Permissions-Policy` 由 `camera=()` 改为 `camera=(self)`，允许同源访问摄像头。
- 注意：`next.config.ts` 变更不热更新，需重启 dev server。

### Orchestrator 日志增强

- **`app/lib/ai/services/orchestrator.ts`**：图片识别完成日志新增 `errorMessage` 与 `imageContentLength` 字段，便于排查 LLM API 错误。

## API 契约变化

### POST /api/solve

**变更前**（同步）：
```json
{
  "success": true,
  "data": { "html": "...", "validated": true, "cached": false }
}
```

**变更后**（异步）：
```json
{
  "success": true,
  "data": { "jobId": "uuid-v4-string" }
}
```

### GET /api/solve?jobId=xxx（新增）

- 处理中：`{ "success": true, "data": { "status": "processing" } }`
- 完成：`{ "success": true, "data": { "status": "done", "result": Solution } }`
- 失败：`{ "success": false, "error": { "code": "...", "message": "..." } }`
- 不存在：404 `{ "success": false, "error": { "code": "GESP6_JOB_NOT_FOUND", "message": "任务不存在或已过期" } }`
- 缺 jobId：400 `{ "success": false, "error": { "code": "GESP6_INPUT_INVALID", "message": "缺少 jobId 参数" } }`

## 后续影响 / 注意事项

1. **API 契约破坏性变更**：如有外部脚本直接调用 POST /api/solve 解析 `data.html`，需改为先取 `data.jobId` 再轮询 GET。前端已同步改造。
2. **内存任务存储**：当前 `job-store.ts` 为进程内 `Map`，dev 模式下热更新会丢失任务；生产环境单实例下正常。多实例部署需替换为 Redis 等共享存储（暂不在本次范围）。
3. **dev server 需重启**：`next.config.ts` 的 `Permissions-Policy` 变更不热更新，需手动重启 `npm run dev`。
4. **移动端 HTTPS 要求**：`getUserMedia`（摄像头 API）要求 HTTPS 或 localhost 环境，IP 直连访问需配置 HTTPS 才能使用拍照上传。
5. **客户端超时**：前端轮询客户端超时 10 分钟，超过会显示"处理超时"提示；任务在服务端仍会继续执行（job TTL 30 分钟）。
