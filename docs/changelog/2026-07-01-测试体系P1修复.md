# 测试体系 P1 级问题修复

**日期**：2026-07-01
**类型**：新增
**影响范围**：测试覆盖提升（fs-html-cache 单测 / 组件纯函数单测 / E2E 并行 / 全局测试配置）

## 变更背景

P0 修复后覆盖率基线为 70.23%，存在 4 项 P1 级不足：
1. **fs-html-cache.ts 无独立测试**（11.49%，文件系统缓存是核心持久化路径）
2. **组件层零覆盖**（validateFile 验证逻辑未测试）
3. **E2E 全串行**（@fast 类不依赖 LLM，可并行提速）
4. **缺 setup.ts**（testing-standards.md §二 要求全局配置）

本次修复补全低覆盖模块、提升执行效率、建立全局测试配置。

## 变更内容

### P1-1：fs-html-cache.ts 独立单元测试

- 新增 `app/lib/ai/services/__tests__/fs-html-cache.test.ts`（14 用例）
- 用 `mkdtempSync` 创建隔离临时目录，测试真实磁盘读写
- 覆盖场景：构造时目录创建、空缓存读取、set + 主 key/内容文件联动、getOrCompute（未命中/命中/inflight 单飞/compute 失败重试）、JSON 损坏容错
- **覆盖率 11.49% → 87.93%**

### P1-2：组件纯函数单元测试

- 导出 `image-uploader.tsx` 的 `validateFile`（原私有函数，加 `export`）
- 新增 `app/solve/components/__tests__/image-uploader.test.ts`（10 用例）
- 覆盖：合法 JPEG/PNG、非法格式（GIF/WEBP/空 type）、大小边界（5MB 通过 / 5MB+1 失败 / 0 字节）、格式优先于大小
- **未引入 jsdom**：三种上传方式（FileReader/getUserMedia/canvas）依赖浏览器 API，jsdom 模拟困难且脆弱，由 E2E 覆盖更合适

### P1-3：E2E 分层并行

- 新增 `npm run test:e2e:fast` 脚本：`--grep "@fast|@smoke" --workers=2`
- @fast/@smoke 类（不依赖 LLM）并行执行，@critical 保持串行（避免 LLM 限流）

### P1-4：全局测试配置 setup.ts

- 新增 `app/lib/ai/services/__tests__/setup.ts`（testing-standards.md §二）
- 统一环境变量默认值（AI_TEXT/VISION_PROVIDER/MODEL + API_KEY/BASE_URL）
- 全局 `afterEach` 清理 mock 调用记录
- vitest.config.ts 配置 `setupFiles`
