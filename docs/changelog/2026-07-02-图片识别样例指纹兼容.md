# 图片识别样例指纹兼容

**日期**：2026-07-02
**类型**：优化
**影响范围**：图片输入路径样例指纹提取、图片识别 Prompt

## 变更背景

用户通过三种方式（URL / 文本 / 图片）提交同一道题时，图片（pic）路径无法命中样例指纹缓存（Plan B），导致重复调用 LLM 生成 HTML。

根因分析：
1. `image-recognition-prompt.md` 明确禁止使用 ```` ``` ```` 代码围栏，要求输出纯文本
2. `extractSampleFingerprint` 仅识别 ```` ``` ```` 代码块，图片识别输出无代码块 → 返回空字符串（FR-003 降级）
3. 降级后跳过 sample 索引查询，无法命中 Plan B 缓存

## 变更内容

### 图片识别 Prompt 修复

- 输出格式模板：样例输入输出内容改为用 ```` ``` ```` 代码围栏包裹（与洛谷等 OJ 平台格式一致）
- 注意事项：整体输出不加代码围栏，但样例 I/O 内容**必须**用代码围栏包裹
- 输出示例：外层改用 4 反引号（`````），内层样例值用 3 反引号包裹

### extractSampleFingerprint 兜底提取

新增 `extractSampleByHeaderPattern` 函数，作为 `extractCodeBlocks` 的兜底方案：
- 当无代码块时，尝试用 `^(输入|输出)(样例)?\s*[：:]` 标题模式提取样例内容
- 支持同行内容（如 `输入：5 2`）
- 不匹配 `输入格式：`/`输出格式：`（避免误提取格式说明）
- 章节头（`## `/`### `/`#### `）结束当前内容块
- 保证兜底路径与代码块路径产出**相同指纹**（核心设计约束）

### 日志字段调整

`extractSampleFingerprint` 日志字段变更：
- `codeBlockCount` → `blockCount`（统一命名，覆盖两种提取路径）
- `codeBlocksPreview` → `blocksPreview`
- 新增 `usedHeaderFallback`（bool，标识是否走了"输入：/输出："兜底路径）

## 后续影响 / 注意事项

- 图片识别路径现在可以通过两种方式命中样例指纹缓存：
  1. **主路径**：Prompt 修复后 LLM 输出代码围栏 → `extractCodeBlocks` 直接提取
  2. **兜底路径**：LLM 未遵循 Prompt 时 → `extractSampleByHeaderPattern` 兜底提取
- 两种路径产出相同指纹，确保与 URL/文本路径的 Plan B 缓存命中一致
- 日志中 `usedHeaderFallback=true` 表示走了兜底路径，可用于监控 LLM Prompt 遵循率
