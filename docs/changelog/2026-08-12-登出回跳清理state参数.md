# 登出回跳清理 state 参数

**日期**：2026-08-12
**类型**：修复
**影响范围**：middleware.ts、middleware 单测、登出回跳首页流程

## 变更背景

上两次修复（2026-08-11）分别解决了登出回跳地址需为绝对 URL（IDP 400 invalid_request）和跨域 POST 页面路由被 Next.js Server Actions 安全校验拒绝（500）的问题。但实际运行中仍有两个遗留问题：

1. **500 错误仍存在**：IDP end_session 的 307 回跳使浏览器以 `Origin: "null"`（跨源重定向隐私上下文值）发起 POST，`isCrossOriginPagePost` 中 `new URL("null")` 抛异常被 catch 吞掉 → 返回 false → 中间件不拦截 → Next.js 仍判为非法 Server Actions 请求 → 500 `[TypeError: Invalid URL] input: 'null'`。

2. **URL 残留 state 参数**：即使 303 转 GET 成功，IDP 回跳附带的 `?state=...` 参数被保留在落地页 URL 中，用户看到 `localhost:3000/?state=...` 而非干净的 `localhost:3000/`。

## 变更内容

### middleware.ts

- `isCrossOriginPagePost`：在 `new URL(origin)` 解析前增加 `origin === 'null'` 判定，直接返回 true（`Origin: "null"` 是跨源重定向的隐私上下文标识，无须也无法解析为 URL host）。
- 跨域 POST 303 重定向逻辑：重定向前从 URL query 中移除 `state` 参数（`redirectUrl.searchParams.delete('state')`）。OIDC 登出 state 仅用于 IDP 回传校验，当前无校验端点（见 logout-service 注释），落地页无需保留。

### __tests__/middleware.test.ts

- 原「跨域 POST 带 query → 303 保留 query」用例更新为「303 移除 state 参数」，断言目标 URL 为 `http://localhost/`（无 query）。
- 新增「Origin: "null"（IDP 307 回跳隐私上下文）→ 303 转 GET 并移除 state」用例。

## 后续影响 / 注意事项

- 该修复仅影响跨域 POST 页面路由的 303 重定向行为，不影响 `/api/*` 与同域请求。
- 若后续实现登出 state 校验端点，需重新评估是否保留 state（当前无校验端点，移除不影响安全性）。
