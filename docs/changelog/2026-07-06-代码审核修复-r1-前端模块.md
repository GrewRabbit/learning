### CR1-003：solve/page.tsx 拆分（466 行 → 26 行）

按评审建议拆分为 3 个文件，每个文件职责单一：

- **app/solve/page.tsx（26 行）**：入口，渲染 header + `<SolveForm />`
- **app/solve/components/solve-form.tsx（261 行）**：表单 UI + 输入控制（inputType/textContent/imageBase64/platformUrl/error/showThinking/showOrganizing）+ `buildProblem` + `?regenerate=true` 自动提交 effect + 折叠面板 UI
- **app/solve/hooks/use-job-polling.ts（275 行）**：自定义 Hook，封装提交（`handleSubmit`）、轮询（`pollJob`）、取消（`handleCancel`/`cancelJobOnServer`）、超时检查、网络错误重试、思考/组织回答内容累积等逻辑，对外暴露 `{ loading, elapsedMs, thinkingContent, organizingContent, handleSubmit, handleCancel }`

**拆分原则**：
- 行为保持不变：所有原有逻辑（轮询间隔 10s、网络错误 3 次上限、客户端超时 30 分钟、思考/组织回答内容更新、Problem 持久化）原样迁移
- E2E selector 全部保留：`#text-content` / `#image-input` / `#platform-url` / 按钮文本"选择文件"/"粘贴图片"/"拍照上传"/"生成解题方案" / `alt="题目预览"` / `aria-label="清除图片"` / `[role="alert"]` / `p.text-muted-foreground` 含"字符"
- 状态分层：UI 状态（showThinking/showOrganizing/error）留在 SolveForm；业务状态（loading/elapsedMs/thinkingContent/organizingContent）下沉到 Hook
- `useJobPolling` 通过 `onError` 回调将错误传递给 SolveForm 的 `setError`，避免 Hook 直接耦合 UI

### CR1-009：sessionStorage 写入降级处理

在 `use-job-polling.ts` 的 `pollJob` 中，`sessionStorage.setItem(SOLUTION_STORAGE_KEY, JSON.stringify(data.data.result))` 包裹 try-catch：

```typescript
try {
  sessionStorage.setItem(SOLUTION_STORAGE_KEY, JSON.stringify(data.data.result));
} catch {
  // sessionStorage 写入失败（Solution 对象过大超出配额）→ 降级提示，不阻断主流程
  setLoading(false);
  onError('结果数据过大，无法缓存到本地');
  return;
}
```

降级行为：写入失败时停止 loading、提示用户"结果数据过大，无法缓存到本地"、不跳转 `/result`（避免 result 页读取空 sessionStorage 报错）。与相邻的 `PROBLEM_STORAGE_KEY` 写入 try-catch 模式保持一致。

### CR1-016：移除 eslint-disable，改用 ref 模式

原 `solve/page.tsx:101` 的 `?regenerate=true` 自动提交 effect 使用 `// eslint-disable-next-line react-hooks/exhaustive-deps` 绕过依赖检查。拆分到 `solve-form.tsx` 后改用 React 推荐的"ref 持有最新值"模式：

```typescript
const handleSubmitRef = React.useRef(handleSubmit);
handleSubmitRef.current = handleSubmit;

React.useEffect(() => {
  // ...
  void handleSubmitRef.current(problem, true);
}, [setInputType, setTextContent, setPlatformUrl, setImageBase64, setError]);
```

effect 依赖数组显式列出所有 stable setter（React 保证 setter 引用不变），不触发 effect 重新运行；`handleSubmit` 通过 ref 读取最新值，避免闭包过期。无需 `eslint-disable`。

## 后续影响 / 注意事项

1. **E2E 测试不受影响**：所有 POM selector（`tests/e2e-tests/pages/solve-page.ts`）保留，包括 heading/tablist/tab/id 选择器/按钮文本/alt/aria-label/role="alert"/字符计数
2. **`?regenerate=true` 自动提交流程不变**：从 `/result` 跳转回 `/solve?regenerate=true` 后，effect 仍从 sessionStorage 读取 Problem、预填表单、自动提交
3. **Hook 的 `onError` 类型为 `(message: string | null) => void`**：传 `null` 表示清除错误（提交时重置），传 `string` 表示设置错误。SolveForm 直接传 `setError`，类型兼容（`Dispatch<SetStateAction<string | null>>` 接受 `string | null` 子集）
4. **`handleSubmit` 不是 stable 引用**：每次 `useJobPolling` 渲染都产生新引用。SolveForm 中通过 `handleSubmitRef` 持有最新值供 mount effect 读取，避免依赖变化触发 effect 重新运行
5. **后续 r2 评审重点**：验证拆分后行为一致性、`useJobPolling` Hook 边界、`onError` 回调契约
