# 登出回跳跨域 POST 转 GET

**日期**：2026-08-11
**类型**：修复
**影响范围**：middleware.ts、middleware 单测、登出回跳首页流程

## 变更背景

SSO 登出时，IDP 的 end_session 对 `post_logout_redirect_uri` 一律返回 **307**（保留原方法），将 `post_logout_redirect_uri` 表单 body 一并 POST 回我方 `/?state=...`。浏览器对该次请求附带首个跨域 `Origin: https://auth.happyrabbit.top`，Next.js 15.1.6 将「跨域 POST 到页面路由」判定为伪造的转发 Server Actions 请求，安全校验（`x-forwarded-host` vs `origin` 不匹配）失败后中止执行，返回 500：

```
`x-forwarded-host` header with value `localhost:3001` does not match
`origin` header with value `auth.happyrabbit.top` from a forwarded
Server Actions request. Aborting the action.
⨯ [Error: Invalid Server Actions request.] { page: '/' }
POST /?state=... 500
```

## 变更内容

### middleware.ts

- 新增 `isCrossOriginPagePost(req)` 判断：`POST` 方法 && 非 `/api` 前缀 && 含 `Origin` 头 && Origin 宿主 ≠ 请求 host。
- 在 health 检查之后、限流之前，对该类请求先发 `NextResponse.redirect(req.nextUrl.clone(), 303)`：转成 GET、丢弃跨域 body，绕过 Next.js Server Actions 跨域校验，使登出回跳能正常渲染首页；`state` 参数随 query 保留。
- 更新文件头注释，补充跨域 POST 兜底的位置与顺序说明。

### __tests__/middleware.test.ts

- `mockRedirect` 支持第二个参数 `status`（默认 302，兼容既有断言）。
- `createReq` 增加 `method` 参数与 `nextUrl.host` / `clone`。
- 新增「跨域 POST 页面路由 → 303 转 GET」用例组：
  - 跨域 POST `/` → 303 到同 URL
  - 带 `state` query 时保留
  - 跨域 POST `/solve` → 303（GET 后仍走认证墙）
  - 同域 POST 不受影响（继续认证墙 → 302 /login?returnTo=...）
  - 跨域 GET、跨域 POST 到 `/api/*`、无 `Origin` 头的跨域 POST 均不干预
