# 存量缓存文件备份删除与E2E前置适配DB

**日期**：2026-08-20
**类型**：优化
**影响范围**：`data/gesp6/`（删除，已备份）、`tests/e2e-tests/specs/solve-text.spec.ts`（sample 索引检查改为 DB 查询）、`.env.local`（不变，`GESP6_CACHE_DRIVER=db`）

## 变更背景

`data/gesp6/` 文件系统缓存（content 108 html+json、primary 22、sample 9，共 247 文件）经 T7 导入已 100% 迁移至 PostgreSQL（`gesp6_billing` 库 solutions/primary_indexes/sample_indexes 三表），并经 T9 切 `GESP6_CACHE_DRIVER=db` 后应用以数据库为缓存权威源。用户确认磁盘文件不再需要保留在项目目录内，按「先备份再删除」策略清理，释放磁盘并消除双缓存源混淆。

## 变更内容

### 全量核验（删除前，非抽样）

- content 108 文件 → DB 108 行，validated 全部一致，无缺失、无 DB 多余
- primary 22 索引 → DB 22 行，指向不悬空
- sample 9 索引 → DB 9 行，指向不悬空
- 唯一差异项：B2002 对应 content `9c656e59` 在 DB 为 8/19 重新生成的新版（比磁盘 7/6 旧版更新），属正常解题重生成，**非磁盘独有数据**
- 空 html 行 `103ab1c8`（validated=false 降级缓存）：磁盘 html 本就 0 字节，DB 如实镜像

### 备份与删除

- 备份：`/tmp/opencode/gesp6-backup/data-gesp6-20260820-124038.tar.gz`（405K，348 条目含目录，gzip 校验通过）
- 删除：`rm -rf data/gesp6`，删除后确认目录不存在

### E2E 前置适配（solve-text.spec.ts）

- `hasB2002SampleIndex()` 由「检查文件系统 `data/gesp6/sample/` 路径」改为「查询 DB sample_indexes 表」（`solutionDao.getBySampleFingerprint`），与 db 驱动一致
- 原因：删除磁盘数据后原文件系统检查恒返回 false，会导致 B2002 文本方式用例误 skip；DB 中 `3c527f43` 索引真实存在，新逻辑返回 true
- 调用点改 `await`（函数转为异步），头部依赖注释同步更新

## 后续影响 / 注意事项

- **回退能力受影响**：`GESP6_CACHE_DRIVER=fs` 回退模式已无磁盘缓存可读（会全部 miss 走 LLM 重新生成）。完整恢复回退能力需从备份解压 `data/gesp6/` 还原
- 备份存放于 `/tmp/opencode/gesp6-backup/`（非持久目录，重启可能清除）；如需长期保留建议移至持久存储
- `scripts/migrate-fs-cache-to-db.ts` 仍保留（幂等，将来数据已入库时全 skip）；重跑前若 `data/gesp6/` 不存在会因扫描目录缺失跳过（预期行为）
- FsHtmlCache 代码保留（架构 FR-026），仅当前 driver 下不触发
