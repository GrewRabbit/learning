# 代码审核 r1 修复 - 配置文件模块

**日期**：2026-07-06
**类型**：优化
**影响范围**：项目根目录配置文件（next.config.ts、middleware.ts、tailwind.config.ts）

## 变更背景

第 1 轮全量代码审核（`docs/reviews/code-review-full-r1.md`）针对配置文件模块提出 3 项问题：

- **CR1-011（P1 重要）**：`next.config.ts` 缺少 `output: 'standalone'`，违反 `cicd-workflow.md` §三与 `deployment-checklist.md` §一，导致 Docker 镜像需打包全量 `node_modules`，体积显著增大。
- **CR1-010（P1 重要）**：`middleware.ts` 仅实现速率限制，无任何认证检查，违反 `dev-workflow.md` §五"middleware.ts 做服务端认证检查"。当前 `/api/solve` 完全开放，匿名用户可触发 LLM 调用消耗成本。
- **CR1-008（P0 阻塞）**：`tailwind.config.ts` 的 `theme.extend.colors` 重复定义语义色 Token，违反 `component-rules.md` §七"Tailwind 配置仅保留 content，禁止 theme.extend 重复定义设计 Token"。

本次按审核意见修复上述 3 项问题。

## 变更内容

### next.config.ts（CR1-011）

- 在 `nextConfig` 对象中添加 `output: 'standalone'` 属性
- 生成最小化 standalone 输出（`.next/standalone/` 包含 `server.js` + 仅生产依赖的 `node_modules`）
- Docker 镜像构建时仅需复制 `.next/standalone` + `.next/static` + `public/` 三部分，显著减小镜像体积
- 添加注释说明配置依据（`cicd-workflow.md` §三、`deployment-checklist.md` §一）

### middleware.ts（CR1-010）

- 新增 `PROTECTED_API_PREFIX = '/api/solve'` 常量，标识受保护路由前缀
- 新增 `isAuthenticated(req: NextRequest): boolean` 钩子函数（当前返回 `true`，注释 `TODO` 待 SSO/LDAP 方案确认后实施真实认证逻辑）
- 在 `middleware` 函数中、速率限制之前插入认证检查：受保护路由未认证时重定向至 `/login`
- 保留原有速率限制逻辑与健康检查豁免逻辑，不破坏
- 文件头注释补充认证检查说明，明确 Edge Runtime 约束（禁止 `logger`，仅用 `console`）
- 严格遵守 Edge Runtime 限制：未引入 `logger`、未使用 Node.js 原生模块

### tailwind.config.ts（CR1-008，尝试修复后回滚）

- **尝试**：按审核建议移除 `theme.extend.colors` 与 `theme.extend.borderRadius`，仅保留 `content`
- **验证结果**：`npm run build` 失败，错误为 `The 'border-border' class does not exist`
- **根因分析**：项目当前使用 **Tailwind v3.4.17**（非 v4），审核建议"Tailwind v4 自动解析 CSS 变量"的前提不成立。Tailwind v3 必须通过 `theme.extend.colors` 定义颜色 Token 才能识别 `bg-card` / `text-destructive` / `border-border` 等语义类名；`globals.css` 中的 `@apply border-border` 也依赖该映射
- **回滚处理**：恢复 `theme.extend.colors` 与 `theme.extend.borderRadius` 原始内容，仅补充说明性注释解释保留原因与未来升级路径
- **globals.css 核对结论**：所有语义色 CSS 变量均已定义（含 `--color-success` / `--color-warning` / `--color-info` 及对应 foreground），无缺失
