# 测试命令体系分层与 E2E 配置完善

**日期**：2026-07-01
**类型**：优化
**影响范围**：package.json、playwright.config.ts

## 变更背景

项目 E2E 测试中 `@critical` 标签用例依赖真实 LLM API（每次调用 30-60 秒），全量 E2E 耗时约 3-4 分钟，本地迭代与 PR 前置检查均跑全量过于低效。原 `test:e2e:fast` 用 `--grep "@fast|@smoke"` 写法在新增非 @fast/@smoke 标签时会漏掉用例，且缺少"单元+集成 + E2E 快速"的组合命令。

需要建立清晰的测试命令分层体系，方便开发者按场景选择：

| 场景 | 命令 | 耗时 | 适用时机 |
|------|------|------|---------|
| 最快烟测 | `test:e2e:smoke` | 秒级 | PR 前置检查 |
| 排除 LLM | `test:e2e:fast` | ~1 分钟 | 本地迭代 |
| 仅 LLM | `test:e2e:critical` | ~2-3 分钟 | 发布前 LLM 链路验证 |
| 全量 E2E | `test:e2e` | ~3-4 分钟 | 完整 E2E 验证 |
| 单元+E2E 快速 | `test:quick` | ~1.5 分钟 | 本地快速反馈（推荐日常） |
| 单元+E2E 全量 | `test:full` | ~4-5 分钟 | 发布前完整验证 |

## 变更内容

### package.json 调整

- `test:e2e:fast` 由 `--grep "@fast|@smoke"` 改为 `--grep-invert "@critical"`，更直观表达"排除耗时用例"，且后续新增非 @critical 标签用例自动纳入
- 新增 `test:quick`：先跑 `vitest run`（单元+集成），再跑 E2E 非 @critical（`--workers=2` 并行）
- 新增 `test:full`：先跑 `vitest run`，再跑全部 E2E（含 @critical）

### playwright.config.ts 注释完善

补充标签策略说明与命令体系对应表，方便开发者查阅：

- `@smoke`：关键路径烟测（秒级），不依赖 LLM
- `@fast`：快速 UI/API 校验（秒级），不依赖 LLM
- `@critical`：完整流程测试（分钟级），依赖真实 LLM API + g++

## 后续影响 / 注意事项

1. **`test:e2e:fast` 语义变化**：从"匹配 @fast|@smoke"改为"排除 @critical"。新增非 @critical 标签的用例（如未来可能的 `@integration`）会自动纳入 fast 集合，需谨慎打标签
2. **`test:quick` 与 `test:full` 依赖 dev server**：Playwright webServer 配置 `reuseExistingServer: true`，本地需先 `npm run dev` 或由 Playwright 自动启动
3. **CI 流水线建议**：`.github/workflows/pr-check.yml` 当前用 `npm test`（仅单元+集成），可考虑改用 `npm run test:quick` 提升 PR 反馈速度（不含 @critical LLM 调用，避免 CI 卡顿）；`.github/workflows/deploy.yml` 已用 `npm run test:e2e -- --grep @critical`，可改为 `npm run test:full` 完整验证
