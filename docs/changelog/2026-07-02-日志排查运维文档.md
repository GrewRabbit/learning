# 日志排查运维文档

**日期**：2026-07-02
**类型**：文档
**影响范围**：`docs/operations/`、运维流程

## 变更背景

样例指纹缓存层（spec-sample-fingerprint-cache-v1.1）实施过程中，为完整追踪用户提交、contentHash 生成、sample 索引创建等关键业务流程，在 6 个模块共新增 58 个日志点（含 route.ts、orchestrator.ts、code-validator.ts、fs-html-cache.ts、html-cache.ts、problem-fetchers/types.ts）。

此前缺少面向运维的日志排查文档，运维人员难以快速定位：
1. 用户反馈问题时应该 grep 哪些关键字
2. 各日志类目对应的业务意义
3. 不同业务阶段产生哪些日志
4. 常见异常场景的标准排查路径

## 变更内容

### 新增运维文档

- 新增 `docs/operations/日志排查指南.md`，作为系统运维日志查询的统一入口

### 文档结构

文档包含 8 个章节：

1. **日志格式规范**：统一格式定义、日志级别语义、输出位置
2. **日志类目总览**：6 个模块 58 个日志点的完整清单，按模块+子流程分组
   - 模块 A：SolveRoute（接入层，7 点）
   - 模块 B：Orchestrator（编排层，28 点）
   - 模块 C：CodeValidator（验证层，11 点）
   - 模块 D：FsHtmlCache（FS 缓存层，30 点）
   - 模块 E：DualKeyHtmlCache（内存缓存层，22 点）
   - 模块 F：extractSampleFingerprint（指纹层，2 点）
3. **业务提交流程图**：Mermaid 流程图标注 7 个阶段（请求接入→编排分发→三步查询→LLM 生成→代码验证→修正循环→缓存写入+返回）与各阶段日志对应关系，附三类业务路径速查（纯缓存命中 / 完整生成 / 降级返回）
4. **常见问题排查场景**：7 个实操场景
   - 场景 A：提交无响应/响应慢
   - 场景 B：返回结果代码不正确
   - 场景 C：重复提交相同题目仍慢
   - 场景 D：缓存命中率异常下降
   - 场景 E：g++ 编译失败批量出现
   - 场景 F：LLM 调用失败
   - 场景 G：Plan B 回写异常
5. **日志关键字速查表**：21 个核心关键字的模块归属
6. **错误码对照表**：10 个 errorCode 的触发模块、含义、用户侧表现
7. **健康检查指标**：7 个运维监控指标及健康阈值
8. **附录**：日志输出位置、相关文件、相关文档链接
