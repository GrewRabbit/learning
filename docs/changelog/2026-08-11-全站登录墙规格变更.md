# 全站登录墙规格变更（spec/auth v1.3 + arch-sso v1.3）

**日期**：2026-08-11
**类型**：重构
**影响范围**：认证/SSO 模块（middleware.ts、app/api/sso/*、app/login、页面路由保护范围、FR 矩阵）

## 变更背景

业务方确认两项需求：① 站点仅 `http://localhost:3000/`（首页）无需登录，其余页面均需登录态才能打开（全站登录墙）；② 未来在登录基础上开发订单/结算系统，所有资源必须先认证才能访问后续内容。据此将受保护资源范围从「仅 /api/solve」扩展为「全站登录墙」，并预留订单系统认证接入。

## 变更内容

### spec-sso-auth：v1.2 → v1.3（approved）

- 新增 FR-028（公开白名单 `/`、`/login`、`/api/sso/*`、`/api/health` 等）、FR-029（页面路由需登录：middleware 302 + returnTo + Node 层深校验判定准则）、FR-030（/login 登录入口页）。
- 修改 FR-016（受保护资源范围扩至全站）、AC-018；新增 AC-035~039、US-006、NFR-007（全部业务资源先认证后访问，订单系统预留）。
- §3.8 新增（页面层认证落点）；§7 拆为已裁决（OQ-002/003/004、OQ-001 部分、OQ-010）与待确认（OQ-005~009）。

### arch-sso：v1.2 → v1.3（approved，含附属文件 arch-sso-dataflow.md、arch-sso-fr-matrix.md）

- AD-01 受保护资源范围改为全站登录墙（D-001）；matcher 扩展覆盖页面路由（D-002）；新增 AD-14 页面层认证落点 requireAuthPage（D-003）；公开白名单常量显式化（D-004）；/login 入口页落地（D-005）；订单系统认证预留（D-006，§8.3）。
- middleware matcher 三分类：不进 matcher（`/login`、`/_next/*`、favicon、metadata 根资源）/ 进 matcher 豁免认证（首页 `/`、`/api/sso/*`、`/api/health`、`/{locale}/login`）/ 豁免限流（仅 `/api/health`）。
- 未认证响应按路径差异化：页面 302 + returnTo（FR-029）/ API 401 JSON（FR-016）。
- 新增风险 R-14（白名单误配死循环）、R-15（页面 Node 校验遗漏）、R-16（页面 HTML 计入限流配额未评估）。
- §4 数据流拆分至 arch-sso-dataflow.md（主文档 477 行 ≤500）。
- 无新增依赖（jose ^6.2.8 已在 package.json）。
