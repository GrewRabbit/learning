**产出**（执行者：nextjs-backend-expert；DAO 粒度按 AR1-010 落定 4 文件）：

- `app/lib/db/connection.ts`：getPool() 惰性单例（max/idle 30s/connectionTimeout/statement_timeout 经 pg 原生连接参数 startup packet 下发）+ getDb() Drizzle 惰性单例 + Db/DbTx/DbClient 类型
- `app/lib/db/daos/`：user-dao（getOrCreateUser 单事务幂等建档含 quota 初始化 + deductFreeFirst/getBalance/addRecharge）、solution-dao（读三分支 + upsert* DO UPDATE + insertIfAbsent* DO NOTHING 带返回布尔）、access-dao（insertAccessIfAbsent）、billing-dao（consume/recharge 流水 + solve_records）
- 单测：`__tests__/`（errors 22 + connection 4 + config 7）+ `daos/__tests__/`（user 10 + solution 14 + access-billing 6），共 **63 用例全 mock 零真实 DB**

**验收结果**（总调度独立复核 + 复跑命令）：
- `npm run type-check` 0 错误 / `npm run lint` 0 警告 / `npm run test:unit` **619 通过 / 4 跳过**
- deductFreeFirst 单条 `UPDATE ... FROM (子查询) prev RETURNING 新旧双列` 与架构 §4.3 定稿 SQL 逐行一致（SET CASE/WHERE 守卫/来源判定，AR1-017 单语句无竞态窗口）
- getOrCreateUser 三步事务（建档→查 id→建账户）语义等价 AD-05（语句序因 quota FK 依赖 users.id 调整，同事务内等价）
- upsert\*（onConflictDoUpdate）与 insertIfAbsent\*（onConflictDoNothing+returning）冲突策略分离断言到位（AR1-001）

**计划内偏差（已评估放行）**：
1. 未建独立 `db.ts`：`export const db = drizzle(getPool())` 会在模块求值期触发 getDbConfig()（DATABASE_URL 缺失时 import 即抛错，违反 AD-02 惰性原则）→ 改为 connection.ts 内 `getDb()` 惰性单例，架构 §5.1 本只定义 getPool()
2. poolMin 不传入 pg Pool（pg 8.x 无 min 预热参数，传了不生效）；配置语义保留在 getDbConfig
3. statement_timeout 用 pg 8.23 原生连接参数（已核实经 startup packet 下发，服务端强制）

**交接 T3 注意**：billingService 直接使用 `getDb()/DbTx`（from connection.ts）；`SolutionWithHash` 本地别名在 T4 类型扩展后自然合并。
