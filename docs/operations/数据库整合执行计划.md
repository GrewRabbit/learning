## 二、核心业务口径（速查）

**计费规则**（以 `userSolutionAccess` 表为唯一权威）：
- 用户首次获取某解法（`contentHash`）→ 计费 1 次（无论缓存是否命中）
- 已获取过 → 免费返回，不重复计费
- 同一题多种解法（不同 `contentHash`）→ 各自对用户单独计费
- `validated=false` 降级返回 → 视为成功获取，按首次获取计费
- 任务失败 / 取消 → 不计费
- 扣减顺序：**免费额度优先**（`free_balance` → `recharge_balance`）

**部署形态**：多实例，计费/额度以数据库为权威（事务 + 唯一约束 + 条件更新防超扣）

**故障策略**：默认 fail-closed（DB 不可用拒绝解题）；`GESP6_BILLING_DEGRADE_OPEN=1` 显式开启 fail-open（应急，不计费不写任何 DB 记录）

## 三、新建库相关步骤（DBA 前置，在数据库服务器执行）

> 详细语句见 [arch-db-integration-schema.md](../architecture/arch-db-integration-schema.md) §3。以下为清单概览：

1. **确认版本**：PostgreSQL ≥ 13（`gen_random_uuid()` 内置）
2. **创建数据库**：`CREATE DATABASE gesp6_billing`
3. **创建最小权限应用账号**：`CREATE ROLE gesp6_app LOGIN PASSWORD '<强密码>'`，仅授 `gesp6_billing` 库的 CONNECT + 库内 schema 权限，禁超级用户
4. **配置连接串**：`DATABASE_URL=postgres://gesp6_app:<密码>@<DB_HOST>:5432/gesp6_billing`，写入 `.env.local`（权限 600，禁进版本库），变量名登记 `.env.local.example`
5. **验证连通**：`psql` 空库 `\dt` 应显示无表
6. **执行迁移建表**：`npm run db:migrate`（8 张表，见 §五实施步骤 2）

## 六、上线顺序（多实例注意）

1. 数据库服务器执行 §三 建库步骤（DBA）
2. 部署代码（依赖 + 迁移 + DAO + 服务 + route + DbHtmlCache），`GESP6_CACHE_DRIVER` 暂保持 `fs`
3. 执行 `npm run db:import` 一次性导入存量缓存（108 html / 22 primary / 9 sample）
4. 全部实例同步将 `GESP6_CACHE_DRIVER=db`（作为统一部署步骤，避免实例间缓存源不一致）
5. 验证旧题缓存命中、新用户计费、余额不足拒绝
6. 写 `docs/changelog/` 更新日志（结构化修改必须记录）

**回退**：`GESP6_CACHE_DRIVER=fs` 即回退文件缓存；`data/gesp6/` 与 `FsHtmlCache` 代码保留，不删除。

## 七、已确认的边界（不做的内容）

- 不做在线支付 / 用户自助充值（人工充值：DB 直改或预留入口）
- 不做 Redis 限流改造、不做 job-store 入库、不做管理后台页面
- 不做 DB 级审计表、不做读写分离 / 分库分表 / HA 集群
- SSO 认证机制不变（不依赖 DB）；`guard.ts`、`middleware.ts`（Edge）不改，Edge 禁止引用 DB
